# 자메스가 푸는 방식 — 3대 차별점

### 1. 🔒 로컬-퍼스트 (Local-first)
외부 API 호출 0회. 인터넷을 끊어도 답합니다.

### 2. 📎 근거 기반 추론 (Evidence-based)
모든 답에 **출처 문서 + 추론 경로 그래프**가 따라옵니다.

### 3. 👮 권한 검사 (Policy-aware)
"검색 결과를 가린다" 가 아니라 **검색 단계부터 권한이 적용**됩니다.

# 자메스가 **대체하지 않는** 것

> ❌ ERP, 회계, 재고, 예약, POS — **그대로 쓰십시오.**

자메스는 그 위에 얹는 **검색 · 분석 · 정책** 레이어입니다.

| 영역 | 누가 담당 |
|---|---|
| 거래 처리 (주문·결제·예약) | **기존 ERP/POS** |
| 마스터 데이터 (고객·재고·원장) | **기존 시스템** |
| 문서·정책·규정·매뉴얼 검색 | **JAMES** |
| "왜 이 결정?" 근거 추적 | **JAMES** |
| 권한 기반 안전한 답변 | **JAMES** |

# 어떻게 동작하나 (5단계)

```
   질문                 ← 사용자
    ↓
   ① 권한 검사          ← 이 사람이 이 정보를 볼 자격이 있는가?
    ↓
   ② 검색 + 그래프      ← 사내 문서에서 관련 근거 수집
    ↓
   ③ 추론 (LLM)         ← 근거 위에서만 답을 구성
    ↓
   ④ 출력 필터          ← 개인정보·권한 외 내용 마스킹
    ↓
   ⑤ 감사 로그          ← 누가/언제/무엇을/왜 (append-only)
    ↓
   답변 + 출처 + 추론경로
```

# 누구에게 잘 맞나

### ✅ 강한 fit

- 사내 문서가 많고, 직원마다 봐야 할 범위가 다른 회사
- 분쟁·감사·규제 대응이 일상인 업종
- "클라우드에 데이터 못 올린다" 가 정책인 곳
- "왜 이 답?" 이 답 자체보다 중요한 의사결정

### ❌ 안 맞는 곳

- 실시간 거래 처리(POS·예약·원장) → ERP 영역
- 워크플로/결재 엔진 → BPM 도구 영역
- 단순 대량 요약 → 더 가벼운 파이프라인이 저렴

# 왜 "도메인팩" 구조를 고집하나

```
        ┌──────────────────────────────┐
        │   JAMES Mother (모체)        │
        │  검색 · 추론 · 권한 · 감사   │
        └──────────────┬───────────────┘
                       │  플러그인
        ┌──────┬───────┼───────┬──────┐
        ▼      ▼       ▼       ▼      ▼
      카페   법무    여행    유통   (귀사)
```

- 모체는 **한 번** 단단하게 만든다.
- 도메인팩은 **모체 코드 0줄 수정 없이** 끼운다.
- 윈도우 위에 한글·엑셀이 따로 깔리는 구조와 같습니다.

→ 회사가 늘어날수록 **다음 회사가 더 빨리·싸게** 도입됩니다.

# 부록 A — 자주 받는 질문

**Q. ChatGPT/클로드 쓰면 되는데 왜?**
A. 그분들은 회사 데이터를 외부로 보냅니다. 자메스는 안 보냅니다.

**Q. 그럼 보안만 다른 거?**
A. 아닙니다. **근거 추적 + 권한 검사**가 검색 단계부터 적용됩니다. 외부 LLM에 RAG 붙여도 "권한 없는 사람이 권한 있는 문서를 검색하는" 문제는 풀리지 않습니다.

**Q. 너무 일러 보입니다. 안전한가요?**
A. 맞습니다. 그래서 **v0.2 단계라고 먼저 말씀드립니다.** 지금 들어오시는 건 PoC 파트너 자격이지 production 도입이 아닙니다.

**Q. 자가학습 한다는데, AI가 멋대로 바뀌나요?**
A. 아닙니다. **사람이 승인하지 않으면 단 한 줄도 적용되지 않습니다.** 이 보장이 깨지는 건 버그입니다.
