## 3. Phase 3.3 — 어떻게 끝냈나

남은 26건 중 24건이 실작업이었고 (2건은 주석), 성격에 따라 갈랐습니다.

### 3.1 열거 가능 16건 → 클래스 (#1107)

boolean 이거나 3~5 outcome 의 lookup 이었습니다. #1101 / #1104 가 찾은
것과 같은 모양 — **보간된 값이 계산된 값은 아닙니다.**

페이저 버튼은 이미 `disabled` 속성을 달고 있어서 cursor/opacity 쌍이
전용 클래스가 아니라 `:disabled` 규칙이 됐습니다.

`.role-badge` 가 아니라 **`.source-role-badge`** 입니다 — 앞 이름은
`chat.css` / `tokens.css` 의 로그인 칩이 이미 쓰고 있고 `graph.html` 이
둘 다 로드합니다.

### 3.2 진짜 계산값 8건 → data-* + CSSOM (#1108)

CSSOM 쓰기는 CSP 관할이 아닙니다 (#1095 측정). 변하는 값만 `data-*` 로
싣고 `innerHTML` 이후에 적용하며, 그 주변의 정적/열거 가능 부분은 클래스로
남깁니다.

**레이더 상관 엣지는 일부러 `stroke-width` presentation attribute 로 하지
않았습니다** — `admin.css` 의 `.char-radar .corr-edge` 가 `stroke-width`
를 지정하고, **CSS 규칙은 presentation attribute 를 이깁니다**. 인라인
값만이 예전과 같은 방식으로 계속 이깁니다. `3.4` 를 지정하는 `.active`
변종에 대고 확인했고 여전히 `2.35px` 로 계산됩니다.

도메인 색은 `core/knowledge_tracker.py` 에 그대로 뒀습니다 — 6개를
`tokens.css` 로 복사하면 팔레트 소유자가 둘이 됩니다.

### 3.3 도구가 보지 않던 표면 2가지 (#1108)

`--report` 가 0 이어도 놓칠 것을 훑다가 나왔습니다:

- `graph_node_editor.js` 가 `setAttribute('style', …)` 로 버튼을 만들고
  있었습니다. 그건 style **속성**을 쓰므로 strict `style-src` 가 마크업
  안의 인라인과 똑같이 차단합니다 — 그런데 태그처럼 생기지 않아서 태그
  정규식이 볼 수 없었습니다. 완전 정적이라 `.node-edit-btn` 이 됐습니다.
- **JS 파일 10개가 `JS_FILES` 목록에 아예 없었습니다.** 파일별 리포트가
  그것들만 빼고 세고 있었던 겁니다. 지금은 style 속성이 없지만, 목록에
  넣었으므로 새로 생기면 보입니다.

둘 다 도구에 반영했습니다.

## 4. `style-src` 졸업 (#1109)

두 절반이 다 끝나서 (#1062 = 서빙 HTML, #1097–#1108 = JS) 지시문이
허용할 게 남지 않았습니다:

```
- style-src 'self' 'unsafe-inline' https://fonts.googleapis.com
+ style-src 'self' https://fonts.googleapis.com
```

**모드는 건드리지 않았습니다.** `JAMES_CSP_MODE` 는 여전히 `report-only`
기본값이라 돌아가는 인스턴스를 깨뜨릴 수 없습니다. 회귀를 운영자 콘솔에
**보이게** 만들고, enforce 로 띄우는 운영자가 실제로 보호를 받게 합니다.

### 4.1 `scripts/csp_enforce_probe.py` (신규)

서버를 띄우지 않고 enforce 헤더 아래에서 5개 페이지를 로드해 위반을
셉니다. Playwright 가 모든 요청을 디스크에서 합성 오리진으로 이행하므로
`'self'` 가 의미를 갖습니다 — #1095 의 측정을 리스너 없이 하는 것입니다.
정책은 `CSP_DIRECTIVES_DEFAULT` 에서 **만들어 쓰므로** 서버가 보내지 않는
헤더를 시험하는 쪽으로 표류할 수 없습니다.

**style-src 위반 0건, 5/5 페이지.**

한계는 명시해 둡니다: 백엔드가 없어서 API 데이터로 그리는 admin 뷰는
렌더되지 않습니다. 그쪽은 #1107 / #1108 의 계산 스타일 쌍 대조와 소스
레벨 가드가 덮습니다.

### 4.2 🔴 프로브가 찾은 **다른** 플립 블로커

`graph.html` 이 `unpkg.com` 에서 라이브러리 3개를 불러오고
(`three`, `3d-force-graph`, `d3-force-3d`), **`script-src 'self'` 가
셋 다 차단합니다.**

선재 문제이고 (#855 이후 `script-src` 는 계속 `'self'`) 지금은 모드가
report-only 라 무해합니다. 그러나 **오늘 enforce 로 플립하면 3D 그래프
뷰가 죽습니다.** 로컬 우선 시스템이니 vendoring 이 답이고, 그건 style-src
PR 의 부수효과가 아니라 operator 판단입니다.

→ **로드맵 §4.4 의 "26 → 0 이 된 뒤 플립" 은 이 항목이 해결돼야 합니다.**

### 4.3 가드

마이그레이션 lock-test 는 전에는 권고였습니다 — 인라인이 다시 들어오면
"나중에 플립이 어려워진다" 였죠. 이제는 enforce 아래에서 **깨진 UI** 를
뜻하므로 표면 전체로 넓혔고, 도구의 파일 목록을 믿지 않고
`frontend/static/*.js` 를 직접 훑습니다:

- JS 가 내보내는 `style="..."` 0건
- `setAttribute('style', …)` 호출부 0건
- 서빙 페이지의 인라인 `<style>` 요소 0건

주석은 스캔 전에 제거합니다 — 여러 주석이 금지 대상 패턴을 인용하면서
그 금지를 설명합니다. **각 가드는 자기 모양의 프로브를 심어 실패하는지
확인했고, 셋 다 실패합니다.**

## 5. 검증이 실제로 잡은 것

전 세션 §5 를 이어받아, 이번에 대조가 잡은 것들입니다.

1. **잘못 짝지어진 셀렉터** (#1107) — `-title` 쌍이 제목이 아니라
   **바깥 행**을 읽고 있었습니다. `A.querySelector('div > div')` 는
   `#A > .first-run-row` 에 먼저 매치됩니다. 양쪽이 같은 잘못된 요소를
   읽고 있었으므로 **일치했습니다**. #1101 의 오짝 함정과 같은 것 — 대상을
   명시적으로 표시하니 primary 제목이 `accent-fg` / `600` 으로 해석됩니다.
2. **죽은 셀렉터 2종** (#1109) — `mobile.css` 의
   `[style*="min-width:…"]` ×4 는 아무것도 매치하지 않았고,
   `#dash-chart > div[style*="display:flex"]` **도** 죽어 있었는데 이건
   문제였습니다: #1099 가 그 래퍼의 인라인을 클래스로 옮길 때 매치가
   끊겨 **대시보드 차트가 폰에서 가로 스크롤을 조용히 잃었습니다.**
   데스크톱 폭 시각 회귀는 못 봅니다 — #1099 자신이 찾은 것과 같은
   사각지대입니다. `.dash-chart-bars` 로 다시 고정했습니다.
3. **`/dev/null`** (#1110) — `tests/_lrb_fixtures.py` 가 픽스처 빌더의
   stdout 을 `open("/dev/null", "w")` 로 죽입니다. **Windows 에는 그 경로가
   없습니다.** 픽스처가 없을 때만 도는 분기라, 픽스처가 있는 체크아웃에서는
   숨어 있었습니다. 새 worktree 에서 LRB 3개 파일이 **수집 단계에서** 실패해
   드러났습니다. `io.StringIO()` 로 고쳤습니다 — 플랫폼별 경로가 아예 필요
   없습니다.
4. **`--apply` 가 여전히 비파괴적인지** (#1108) — 수집할 게 없어진 지금
   #1097 의 실패 모드가 재현되는지 확인: 규칙 462개 → 462개, 손실 0,
   추가 0, 본문 변경 0. 실행은 carried-forward 버킷으로 **재정렬만** 합니다.

## 6. CI `--ignore` 51 → 0 (#1111)

목록에는 반복 계획이 달려 있었습니다 — CI 의존성이 생기거나 (Ollama 서비스
컨테이너) 격리가 개선되면 (DB 픽스처 정리, TestClient app-factory) 하나씩
회수한다. **그 계획은 이미 추월당해 있었습니다 — 파일들은 통과하고 있었고
아무도 확인하지 않았습니다.**

"내 머신에서는 통과한다" 가 바로 무시 목록이 막으려는 것이므로, 그 변명을
없애도록 측정을 구성했습니다:

- **detached git worktree** — `.env` 는 untracked 라 새 체크아웃 = 새 클론
- `OLLAMA_API_URL` / `OLLAMA_HOST` 를 **죽은 포트**로. 진짜 Ollama 가 필요한
  것은 이 머신에서 도는 인스턴스에 조용히 닿는 대신 즉시 실패
- 환경변수를 **73개 덜어낸** 최소 환경. 개발 셸이 지니고 러너는 갖지 않는
  실제 서비스 키가 빠집니다 (`TAVILY_API_KEY` 포함 — config 배너가
  DuckDuckGo fallback 으로 바뀌어 제거가 실제로 먹혔음을 보여줍니다)

| 검사 | 결과 |
|---|---|
| 51개 각각 단독 실행 | **51 / 51 통과** |
| `tests/` 전체 동시 실행 | **5,312 passed / 0 failed** |
| 최장 테스트 vs 30s timeout | **6.6s** |

러너와의 차이는 둘 남습니다 — **ubuntu vs Windows, 3.11 vs 3.14** — 그래서
**이 PR 의 CI 실행이 진짜 증거**이지 로컬 실행이 아닙니다.

**그 실행이 초록입니다**: `5,309 passed / 0 failed / 8 skipped`, 2분 25초
(run 34349540062). CI 가 실제로 도는 테스트가 **4,469 → 5,309 (+840)** 로
늘었습니다.

파일이 돌아와야 한다면 **목록이 아니라 그 파일 하나로** 돌아옵니다.
제거한 블록 자리에 그 취지와 측정 방법을 주석으로 남겼습니다.
