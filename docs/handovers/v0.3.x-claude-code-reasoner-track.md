## 1. Problem

자메스의 추론 깊이는 현재 두 가지로 제한됩니다:

| 경로 | 한계 |
|---|---|
| 내장 LLM 합성 (Gemma / 로컬) | reasoning depth 제한, 도구 사용 불가 |
| 외부 LLM (Anthropic API direct) | 토큰 단가 누적, prompt caching 수동 |

본 사이클은 **세 번째 경로**를 추가합니다: 사용자의 Claude Max 구독으로
이미 인증된 **Claude Code CLI** 를 subprocess로 호출해 한 subtask의
deliberative reasoning을 위임하고, 그 트레이스를 자메스 자산으로
적재해 *다음 쿼리에는 RAG로 재활용*하는 경로.

핵심 동기는 **메타-도그푸딩**: 자메스를 만드는 과정 자체가 자메스의
첫 학습 코퍼스가 됩니다. 본인 1인 사용 단계에서 비용 0에 가까운
상태로 트레이스 자산화 가설을 검증한 뒤, 검증되면 BYOK SDK backend
로 확장합니다.

## 2. Non-goals (이번 사이클에서 안 함)

- 모델 가중치 업데이트, fine-tuning, distillation
  — `docs/ARCHITECTURE.md` non-goals 유지.
- Claude Code 자동 호출 / 자동 실행. 모든 호출은 **명시적 트리거**.
- 외부 사용자 배포. v0.3.x 사이클은 본인 1인 도그푸딩 한정.
- 도메인 전용 reasoner (법률·식품 등). CLAUDE.md rule #1.
- Plugin API 정식 stability 약속. v0.3 가 닫힐 때까지 베타.

## 3. Architecture (where it sits)

### 3.1 §5.7 Cognitive Middleware 안에서의 위치

```
Orchestrator
 └─ Domain Specialist
     ├─ backend: GemmaLocalBackend         (기존)
     ├─ backend: AnthropicSDKBackend       (BYOK, 미래)
     └─ backend: ClaudeCodeCLIBackend      ← 본 사이클
```

→ **§5.7.3 multi-agent cap (= 5 roles) 안 깸**. Claude Code는 새
role이 아니라 기존 `Domain Specialist` role의 *backend 구현체*.

### 3.2 새 모듈 (planned)

| 모듈 | 책임 | 크기 가이드 |
|---|---|---|
| `core/reasoning/backends/base.py` | `LLMReasoner` ABC | < 3 KB |
| `core/reasoning/backends/claude_code_cli.py` | subprocess wrapper | < 8 KB |
| `core/reasoning/trace_schema.py` | **정규화 트레이스 스키마** (backend-agnostic) | < 4 KB |
| `core/reasoning/trace_store.py` | normalized trace → cascade artifact 어댑터 | < 8 KB |
| `core/reasoning/trace_backfill.py` | git / PR / handover → historical trace 스캐너 (L1b) | < 10 KB |
| `core/reasoning/historical_scrubber.py` | credential 패턴 스캐너 (L1b 의존, Q3 결정) | < 4 KB |
| `core/reasoning/trace_replay.py` | `audit_bridge` 행 재생 검증 | < 5 KB |

모두 `core/` 20 KB 게이트 안 (CLAUDE.md rule #5).

### 3.2.1 정규화 트레이스 스키마 (backend-agnostic)

raw Claude Code 세션 JSON을 그대로 적재하지 않습니다. 모든 backend·
모든 source(live / historical)가 같은 shape로 들어와야 다른 코더 LLM
(Aider / Cursor / 로컬 코더) 추가 시 마이그레이션 비용 0.

```jsonc
{
  "trace_id": "uuid",
  "source": "live" | "historical",          // live = subprocess capture, historical = backfill
  "backend": "claude_code_cli" | "git_history" | "pr_review" | "handover_doc" | ...,
  "intent": "string",                        // 정규화된 문제 진술
  "prompt_summary": "string | null",         // historical 은 null 가능
  "file_diffs": [ { "path": "...", "diff": "..." } ],
  "tool_calls": [ { "tool": "...", "args": {...}, "result_sha256": "..." } ],
  "outcomes": { "tests_passed": int, "files_changed": int, "merged_pr": int | null },
  "curated": bool,                           // approver_username 게이트 통과 여부
  "approver_username": "string | null",
  "created_at": "iso8601",
  "links": { "commit_sha": "...", "pr_number": int, "handover_path": "..." }
}
```

→ retrieval 시 `backend` 필터로 "Claude식 풀이"만 보거나 "PR 리뷰
패턴만" 추출 가능. **Q1 (backend-agnostic asset) 충족.**

### 3.3 트러스트 존 (§5 amendment 필요)

`docs/ARCHITECTURE.md §5` Trust Zone 표에 한 행 추가 — 별도 PR
(`architecture` 라벨, CLAUDE.md rule #4):

| Zone | Source | Default trust | Hardening |
|---|---|---|---|
| **External LLM reasoner** | Claude Code CLI / Anthropic SDK | **low** | `extract_data_only()` + PolicyEngine `can_emit` + curated 플래그 |

→ Claude Code 출력은 *web search results* 와 같은 트러스트 레벨.
자메스 내부 상태(graph / memory / wiki)에 직접 쓰이지 않으며, 모든
적재는 `audit_bridge` 행 + curated 플래그를 거칩니다.

## 4. Audit & governance (§5.7.2 invariant 충족)

§5.7.2 trace replay invariant: **모든 reasoning step은 audit_bridge에
한 행씩**, 전체 트레이스는 그 행들만으로 복원 가능.

| Step | `audit_bridge` 행 |
|---|---|
| Reasoner 호출 트리거 | `reason_stage=reasoner_dispatch`, `backend=claude_code_cli` |
| subprocess 시작 | `reason_stage=reasoner_call_start`, `prompt_sha256=...` |
| subprocess 종료 | `reason_stage=reasoner_call_end`, `output_sha256=...`, `duration_ms=...` |
| 큐레이션 마킹 | `reason_stage=trace_curated`, `approver_username=...` ← CLAUDE.md rule #3 |
| Cascade 적재 | `reason_stage=trace_indexed`, `cascade_artifact_id=...` |

`approver_username` 없는 trace는 **검색 인덱스에 들어가지 못함**
(rule #3). 이 게이트가 self-evolution 안전 규칙을 만족시킵니다.

### 5.1 L1b 의 의의 (자메스만의 비교우위)

자메스의 모든 진화 기록 — 144+ PR, 모든 handover doc, 모든 cycle
rationale, ARCHITECTURE.md 변천사 — 은 이미 디스크에 있습니다.
이걸 일회성 backfill 로 retrievable 코퍼스화하면, 자메스가 자기 자신의
*진화 역사 전체*를 RAG-queryable 자산으로 갖게 됩니다.

세 가지 caveat:

1. **스키마 열화**: historical trace 에는 prompt/response 구조가 없음
   — 결과(diff + 커밋 메시지 + PR 본문)만. `source=historical` 태그로
   표시. 완전한 reasoning 재생은 불가, 그러나 RAG hit 가치는 충분.
2. **노이즈 큐레이션**: 커밋 단위가 아니라 **PR-level** 으로 묶음
   (squash 커밋의 본문이 자연스러운 단위). `architecture` ·
   `priority:high` · cycle-closure 라벨 PR 우선 인덱싱.
3. **PII / secret 스캐닝**: 과거 git 히스토리 credential 누출 가능성.
   L1b 적재 전 `core/data_artifacts.py` scrubber 의무 통과
   (L1b PR 의 verification 체크리스트 항목).

## 6. Backend abstraction (왜 처음부터 ABC인가)

L0 만 보면 ABC는 over-engineering 처럼 보입니다. 그러나:

1. v0.3 Platform Skeleton 트랙의 슬립된 Plugin API (Track C) 가
   본 트랙의 **첫 실제 수요자**. ABC 없이 시작하면 Plugin API 가
   다시 재설계됩니다.
2. 본인 1인 (Max-CLI) → 외부 사용자 (BYOK SDK) → 미래 (로컬 모델)
   확장 경로가 명백. ABC 비용이 회수됩니다.
3. ABC 자체는 < 3 KB 이라 비용 자체가 작음.

단 L2 에서 ABC를 정식 도입하고, L0 는 임시 함수 wrapper 로 출발해
*하루-이틀 안에 트레이스 누적을 시작*하는 게 우선 (속도-우선 슬라이스).

## 7. Decisions (resolved 2026-05-15)

이전 Open Questions 7개 모두 결정 완료. 각 결정은 슬라이스 표(§5)
와 모듈 표(§3.2) 에 반영됨. 결정 후 객관 사유는 다음과 같음.

### Q1 → 호출 형식: **single-shot `claude -p`**
- 이유: 결정적 / 감사 단순 (각 호출이 독립 audit unit).
- 세션 ID lifecycle 관리 부재 → L0 복잡도 ↓.
- prompt caching 이득은 시스템 프리픽스를 프롬프트 내 고정 영역에
  배치하면 single-shot 에서도 일부 회수 가능.
- `--resume` 누적 세션 최적화는 **L2 이후 별도 PR 에서 cost / latency
  실측 후 평가**. L0 단계에서는 비도입.

### Q2 → Curated UI: **admin 패널**
- 이유: 본인 1인 도그푸딩 단계 — 본인이 결정 권한자이자 사용자.
- 챗 UX 안에 "📚 자산화" 칩 추가는 외부 사용자 배포 단계(v0.4+)
  에서 재검토. v0.3.x 사이클에선 admin 패널 단독.

### Q3 → PII / secret scrubbing: **두 단계 파이프라인**
- 단계 1: `core/policy_engine.sanitize_for_ingestion()` (instruction
  injection / attack pattern 제거 — 기존 자산 재사용).
- 단계 2: `core/reasoning/historical_scrubber.py` 신규 모듈
  (credential 패턴 정규식: AWS / GitHub / Anthropic / OpenAI / SSH /
  generic high-entropy token).
- 기존 sanitizer 는 *credential leak 전문이 아님* — 별도 모듈 필수.
- L1b PR 의존성. L1b verification 체크리스트에 scrubber pass log
  의무.

### Q4 → Max rate-limit fallback: **explicit error**
- 이유: silent fallback 은 사용자 신호 손실 + 비결정적 비용 모델.
- L3 PR 에서 `RateLimitExceeded` 예외 raise + audit 행
  `reason_stage=rate_limit_block` 적재.

### Q5 → §5.7.2 와의 관계: **Pre-L0 amendment 로 명시화**
- §5.7.2 의 "working-memory-only" 규칙은 *unverified intermediate
  reflection state* (draft/critique/revised cycle internals) 에 적용.
- 본 사이클이 적재하는 것은 *verified reasoner backend output trace*
  — approver_username 게이트 통과 + curated 플래그 set.
- 이 둘이 별개 카테고리임을 §5.7.2 한 단락 추가로 명시화. **architecture
  라벨 Pre-L0 PR** (CLAUDE.md rule #4 충족).

### Q6 → L1b 백필 범위: **단계적 4 phase + 매 phase 후 ROI 평가**
- Phase 1: `architecture` 라벨 PR (가장 정보 밀도 높음)
- Phase 2: `docs/handovers/*.md` (이미 구조화됨, scrubber 부담 낮음)
- Phase 3: cycle-closure PR (큰 단위 결정 기록)
- Phase 4: 나머지 PR (선택적)
- 매 phase 후 retrieval hit rate / 노이즈 비율 평가. 무조건 4단계
  완주 X — phase 2 또는 3 에서 ROI 포화 시 중단 가능.

### Q7 → Multi-coder 정규화 가설 검증: **L2에 mock + 1 stub 추가**
- L2 PR 에 `claude_code_cli` (실제 구현) + `anthropic_sdk_stub`
  (스키마 검증용 stub, 실제 호출 없음) + `mock_backend` (테스트용).
- 두 비-mock 구현체가 동일 정규화 trace shape 를 산출하는지
  regression 테스트로 가설 검증.
- 추가 LOC 비용 ~50줄 (stub 자체는 응답 형식만 흉내).

## 10. 한국어 요약

자메스 안에서 Claude Code CLI를 호출 → 추론 → 그 트레이스를 자메스
자산(Knowledge Cascade)으로 적재해 다음 검색에 재활용합니다. 본인이
이미 Claude Max 구독자라 **Max-CLI backend로는 추가 비용 없이** 도그
푸딩 가능. 모델 가중치는 안 건드리고, "기억은 남기되 모델은 안
바꾼다" — non-goals 위반 없음.

자산은 처음부터 **backend-agnostic 정규화 스키마** (§3.2.1) 로
적재하므로 향후 Aider · Cursor · 로컬 코더 추가 시 동일 retrieval
surface 에 합류 — 마이그레이션 비용 0.

**Live (앞으로) + Historical (지금까지)** 두 갈래 인제스천. L1b
백필 슬라이스로 144+ PR · 모든 handover · ARCHITECTURE 변천사 ·
