## 1. Problem

자메스의 추론 깊이는 현재 두 가지로 제한됩니다:

| 경로 | 한계 |
|---|---|
| 내장 LLM 합성 (Gemma / 로컬) | reasoning depth 제한, 도구 사용 불가 |
| 외부 LLM (Anthropic API direct) | 토큰 단가 누적, prompt caching 수동 |

본 사이클은 **세 번째 경로**를 추가합니다: 사용자의 Claude Max 구독으로
이미 인증된 **Claude Code CLI** 를 subprocess로 호출해 한 subtask의
deliberative reasoning을 위임하고, 그 트레이스를 자메스 자산으로
적재해 *다음 쿼리에는 RAG로 재활용*하는 경로.

핵심 동기는 **메타-도그푸딩**: 자메스를 만드는 과정 자체가 자메스의
첫 학습 코퍼스가 됩니다. 본인 1인 사용 단계에서 비용 0에 가까운
상태로 트레이스 자산화 가설을 검증한 뒤, 검증되면 BYOK SDK backend
로 확장합니다.

## 2. Non-goals (이번 사이클에서 안 함)

- 모델 가중치 업데이트, fine-tuning, distillation
  — `docs/ARCHITECTURE.md` non-goals 유지.
- Claude Code 자동 호출 / 자동 실행. 모든 호출은 **명시적 트리거**.
- 외부 사용자 배포. v0.3.x 사이클은 본인 1인 도그푸딩 한정.
- 도메인 전용 reasoner (법률·식품 등). CLAUDE.md rule #1.
- Plugin API 정식 stability 약속. v0.3 가 닫힐 때까지 베타.

## 3. Architecture (where it sits)

### 3.1 §5.7 Cognitive Middleware 안에서의 위치

```
Orchestrator
 └─ Domain Specialist
     ├─ backend: GemmaLocalBackend         (기존)
     ├─ backend: AnthropicSDKBackend       (BYOK, 미래)
     └─ backend: ClaudeCodeCLIBackend      ← 본 사이클
```

→ **§5.7.3 multi-agent cap (= 5 roles) 안 깸**. Claude Code는 새
role이 아니라 기존 `Domain Specialist` role의 *backend 구현체*.

### 3.2 새 모듈 (planned)

| 모듈 | 책임 | 크기 가이드 |
|---|---|---|
| `core/reasoning/backends/base.py` | `LLMReasoner` ABC | < 3 KB |
| `core/reasoning/backends/claude_code_cli.py` | subprocess wrapper | < 8 KB |
| `core/reasoning/trace_store.py` | JSONL → cascade artifact 어댑터 | < 8 KB |
| `core/reasoning/trace_replay.py` | `audit_bridge` 행 재생 검증 | < 5 KB |

모두 `core/` 20 KB 게이트 안 (CLAUDE.md rule #5).

### 3.3 트러스트 존 (§5 amendment 필요)

`docs/ARCHITECTURE.md §5` Trust Zone 표에 한 행 추가 — 별도 PR
(`architecture` 라벨, CLAUDE.md rule #4):

| Zone | Source | Default trust | Hardening |
|---|---|---|---|
| **External LLM reasoner** | Claude Code CLI / Anthropic SDK | **low** | `extract_data_only()` + PolicyEngine `can_emit` + curated 플래그 |

→ Claude Code 출력은 *web search results* 와 같은 트러스트 레벨.
자메스 내부 상태(graph / memory / wiki)에 직접 쓰이지 않으며, 모든
적재는 `audit_bridge` 행 + curated 플래그를 거칩니다.

## 4. Audit & governance (§5.7.2 invariant 충족)

§5.7.2 trace replay invariant: **모든 reasoning step은 audit_bridge에
한 행씩**, 전체 트레이스는 그 행들만으로 복원 가능.

| Step | `audit_bridge` 행 |
|---|---|
| Reasoner 호출 트리거 | `reason_stage=reasoner_dispatch`, `backend=claude_code_cli` |
| subprocess 시작 | `reason_stage=reasoner_call_start`, `prompt_sha256=...` |
| subprocess 종료 | `reason_stage=reasoner_call_end`, `output_sha256=...`, `duration_ms=...` |
| 큐레이션 마킹 | `reason_stage=trace_curated`, `approver_username=...` ← CLAUDE.md rule #3 |
| Cascade 적재 | `reason_stage=trace_indexed`, `cascade_artifact_id=...` |

`approver_username` 없는 trace는 **검색 인덱스에 들어가지 못함**
(rule #3). 이 게이트가 self-evolution 안전 규칙을 만족시킵니다.

## 6. Backend abstraction (왜 처음부터 ABC인가)

L0 만 보면 ABC는 over-engineering 처럼 보입니다. 그러나:

1. v0.3 Platform Skeleton 트랙의 슬립된 Plugin API (Track C) 가
   본 트랙의 **첫 실제 수요자**. ABC 없이 시작하면 Plugin API 가
   다시 재설계됩니다.
2. 본인 1인 (Max-CLI) → 외부 사용자 (BYOK SDK) → 미래 (로컬 모델)
   확장 경로가 명백. ABC 비용이 회수됩니다.
3. ABC 자체는 < 3 KB 이라 비용 자체가 작음.

단 L2 에서 ABC를 정식 도입하고, L0 는 임시 함수 wrapper 로 출발해
*하루-이틀 안에 트레이스 누적을 시작*하는 게 우선 (속도-우선 슬라이스).

## 7. Open questions (PR 전 결정 필요)

- **Q1.** Claude Code CLI 호출 형식 — `claude -p "<prompt>"` 단발 vs
  `claude --resume <session_id>` 누적 세션? 후자는 prompt caching 이득
  크지만 세션 ID 관리 복잡도 ↑.
- **Q2.** Curated 플래그 부여 UI — 챗 UX 안 (제안 칩 옆 "📚 자산화")
  vs admin 패널 전용? 본인 1인 도그푸딩 단계는 admin 패널이 빠름.
- **Q3.** Trace 적재 시 PII / secret scrubbing — `core/data_artifacts.py`
  의 scrubber 재사용 가능한가? L1 PR 전 확인 필요.
- **Q4.** Max rate-limit 도달 시 fallback — 조용히 로컬 backend 로
  스왑 vs 명시적 에러? 사용자 신호 손실 위험 → 명시적 에러 권장.
- **Q5.** 본 사이클이 §5.7.2 의 "reflection state is **not** persisted
  by default" 와 어떤 관계인가? 본 사이클은 *최종 출력 트레이스* 만
  적재하므로 invariant 유지. §5.7 문서에 명시 추가 필요.

## 10. 한국어 요약

자메스 안에서 Claude Code CLI를 호출 → 추론 → 그 트레이스를 자메스
자산(Knowledge Cascade)으로 적재해 다음 검색에 재활용합니다. 본인이
이미 Claude Max 구독자라 **Max-CLI backend로는 추가 비용 없이** 도그
푸딩 가능. 모델 가중치는 안 건드리고, "기억은 남기되 모델은 안
바꾼다" — non-goals 위반 없음. 4단 슬라이스(L0→L3)로 각각 독립
PR로 진행하며, §5.7.2 trace replay invariant 와 CLAUDE.md rule #3
(approver_username) 을 첫날부터 강제합니다.
