> 직전 클라우드 세션에서 작성·검증된 핸드오버. PC 세션에서 그대로 참조해 작업 진행.

## Context

v0.1.3에서 모든 LLM 호출이 `RouterWrapper`로 이관된 직후 발생한 회귀로
`core/reasoning_engine.py:920`의 `self.llm.get_cache_stats()` 호출이 500
에러를 발생시킴. 본 문서는 (1) 그 핸드오버 5개 주장을 default 브랜치

감사 결과를 통합해, PC 세션이 v0.1.3.1 핫픽스 + v0.2.0 보안 패치를
순서대로 처리할 수 있게 함.

## ⚠️ Origin & Environment Caveats (반드시 먼저 읽을 것)

본 핸드오버의 관찰 출처는 **PC가 아닌 별도 노트북**입니다:
- 그 노트북에 GitHub에서 신규 clone → 신규 설치 → 가동 시점에 발생한 증상
- Ollama 모델 풀, 하드웨어 사양(RAM/VRAM), `wiki/` 데이터셋, `chroma_db/` 인덱스 모두 PC와 다를 수 있음
- v0.1.2/v0.1.3 릴리스노트의 성능 수치(p50 25.7s → 23.8s, 161 entities, 263 relations 등)는 **노트북 전용** 측정. PC에서 같은 수치 재현 기대 금지

따라서 PART 1·PART 2 항목들은 **환경 독립** (소스코드 사실)과 **환경 의존** (런타임·데이터 사실)으로 나눠 다뤄야 합니다.

v0.1.0 초기 커밋(`d15bf66`)에 포함되었던 PII가 git 히스토리에 잔존
(현재 코드는 `c71799a4`로 정리됨, 그러나 히스토리는 그대로):

| 항목 | 위치 (구) | 영향도 | 회복 가능성 |
|---|---|---|---|
| Windows 사용자명 | 구 `config.py` 2곳 | 중 (정찰 정보) | 어려움 (히스토리 재작성) |

### GitHub Settings (저장소 보안 기능)

`mcp__github__run_secret_scanning`이 "Repository does not have GitHub
Advanced Security enabled" 에러를 반환했으나, 이는 **MCP 도구가
GHAS(유료) 경로를 호출**한 것. 공개 저장소는 무료 secret scanning
별도 수신 가능:

| 기능 | 공개 저장소 | 권장 상태 |
|---|---|---|
| Secret scanning (basic) | 무료 자동 | 활성 확인 |
| **Push protection** | 무료 (수동 활성) | **활성 강력 권장** |
| Dependabot alerts | 무료 자동 | 이미 작동 (#1, #9) |
| Dependabot security updates | 무료 | 활성 권장 |

확인 절차: Settings → Code security → 4개 항목 활성. 웹 UI 필수
(MCP 도구로 alert 탭 직접 조회 불가).
