## 4. 유지되는 규칙

CLAUDE.md 의 rule #1–#5 는 그대로입니다. 이 사이클에서 특히 중요한 것:

1. **rule #1 — v1.0 전 도메인 특화 금지.** Fork A 확정 전까지 유효.
2. **rule #2 — `core/{retrieval,graph,reasoning}` 변경 PR 은 벤치 수치 +
   Quality Delta Card 필수.** Phase 2 의 `engine.py` 분할도 대상입니다
   (`fix` 라벨 면제는 측정 산출물 자체를 고칠 때만).
3. **rule #5 — `core/` 20 KB.** 현재 **2건 위반 중** (§1.1).
4. **NEW rule #6 — 상태는 한 곳에만 (state single-source).** 사이클 상태의 원본은 `docs/handovers/` 의 최신 문서 하나이고, 루트 문서는 거기를 가리키기만 합니다. (§Phase 1)
5. **정직한 프레이밍**: 빨간 결과를 초록으로 재서술하지 않습니다. Phase 2
   에서 테스트를 지워 초록을 만드는 것은 명시적 금지입니다.

## 5. 재개 첫 세션 체크리스트 (30분)

```bash
# 1. 최신 main 확보
git fetch origin main && git checkout main && git pull origin main

# 2. 의존성 재설치 — ruff 포함 (test_eval_pack_script 가 셸아웃함)
pip install -r requirements.txt && pip install ruff

# 3. 현재 빨간불 재현 — Phase 2 의 출발점 (기대값: failures 9 이하)
python -m unittest discover -s tests -p "test_*.py" 2>&1 | tail -5

# 4. 게이트 2종 (둘 다 초록이어야 정상)
python -m unittest tests.test_v06_module_size_gate
python -m unittest tests.test_v06_claude_md_entry_pointer

# 5. 결정론 벤치가 여전히 재현되는지 (제품 건강도의 진짜 지표)
bash benchmarks/run_all.sh
```

4번과 5번이 통과하는데 3번만 빨갛다면 → **제품은 살아 있고 남은 실패는
계약/환경 문제**이며, 로드맵 Phase 2 를 그대로 진행하면 됩니다.
3번이 9건보다 많이 나온다면 **의존성 미설치를 먼저 의심**하세요 — 이
문서의 수치는 의존성이 없는 컨테이너에서 잰 것이라 errors 가 많습니다.
