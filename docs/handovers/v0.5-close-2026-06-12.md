### 5.6 Track F — Mother-level UI surfaces (NEW, added 2026-06-12)

Operator's 2026-06-12 strategy review added two mother-level UI
surfaces that surface the v0.5-landed primitives (G3 corpus
reconstruct, change_request, contradiction_arbiter, etag, approval
evidence) into user-visible viewers. **Solo-doable, no measurement,
no vertical content** — UI is domain-agnostic.

The strategy review framed these as "for legal/audit/compliance
teams" (TT — Time-Travel viewer) and "for legal/medical/compliance
pilot customers" (CR — Change Review workspace). **The viewer
codebase itself is mother-level** — domain framing belongs to the
customer-pilot onboarding flow (Track D, LOI-gated). The viewer
schema is content-agnostic (timestamp picker + graph diff +
side-by-side text panes + approve/reject buttons).

#### F.1 Time-Travel Dashboard

Surfaces `reconstruct_corpus_view_at` (G3, PR #849) +
`reconstruct_graph_at` (T5) + `replay_audit` into a viewer that
**replays graph state + reasoning trail at any past time T**.

| Item | Source | Sketch |
|---|---|---|
| **TT.a** timestamp picker UI | strategy 2026-06-12 §1 | `frontend/graph.html` extension — date/time picker overlay on existing reasoning-graph page. State sync with URL hash so a deep-link replays the same moment |
| **TT.b** corpus-state diff renderer | G3 (PR #849) + T7 | Calls `reconstruct_corpus_view_at(heads, lookup, t)`; nodes/edges colour-coded: active / superseded / invalidated / CASCADE-removed. Reuses existing `graph.html` mint-cyber palette |
| **TT.c** reasoning trail replay | replay_audit + trace_id | Given a `trace_id`, fetches `audit_log` rows up to T and re-renders the reasoning timeline (`retrieve → expand → verify`) in the same 3-phase format the chat panel uses (chat.js STAGE_META) |
| **TT.d** now-vs-T diff view | TT.b + TT.c | Side-by-side: left = current state, right = state at T. Highlights added/removed/changed nodes. Citation cards link to `audit_log` rows that justify the diff |

**Why mother-level**: viewer reads timestamps + graph nodes + audit
rows; carries no domain schema. Legal/audit operators are the
target USER, but the UI doesn't carry "contract" or "policy"
content beyond what the underlying ontology (B.5.b 10 horizontal
subtypes) provides.

**Maps to procurement value**: RAB v0.1.1 headline (`AC/RF/PC =
1.000 × 3`) becomes a **visual demo** — instead of a number, the
auditor sees the replay in a browser. EU AI Act Art. 12 evidence
surface directly visible.

## 6.5 Rule #1 protection layer (cross-track)

CLAUDE.md rule #1 ("no domain features until v1.0") is preserved
across Tracks A/B/C/E/F by **four mechanical layers**, enforced
on every v0.6+ PR:

| Layer | Mechanism | Source |
|---|---|---|
| **Code-level** | `rule_one_exemption_granted` capability default empty → `register_pack` raises `CapabilityNotGrantedError`. Vertical pack code cannot run | B.3 §4.3 |
| **Doc-level** | Every PR's "Out of scope" section explicitly states "vertical content BLOCKED per CLAUDE.md rule #1 until v1.0 / LOI" | v0.5 PR pattern (used by #842-#861) |
| **Naming-level** | UI surfaces use domain-agnostic names. ✗ "법무팀 Console" / "Compliance Workspace" / "Legal Review Page" — ✓ "Change Review Workspace" / "Time-Travel Dashboard" | F.2 §"Rule #1 framing discipline" |
| **Trigger-level** | LOI-gated work (Track D, G8.d, F.2-CR.e, vertical pack) explicitly tagged in PR description and CLAUDE.md "Where to look next" | v0.5 close handover §5 pattern |

A PR that violates any layer is reviewer-rejectable until corrected.
The four layers compose so that a PR slipping past one layer still
fails another.
