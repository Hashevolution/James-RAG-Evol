## 0. ★ Scope disclaimer (사용자 catch 정정, 2026-06-11 추가)

**LRB 가 측정하는 것**: 검색 (retrieval) — "T 시점에 valid 한 문서를
top-k 안에 가져왔는가". R@k / P@k / temporal_accuracy / R@1 / latency
/ token cost 모두 **retrieval axes**.

**LRB 가 측정하지 않는 것**: 추론 (reasoning) — "retrieved 문서를
이해해서 정답을 생성했는가" / "multi-hop 추론으로 결론 도출했는가" /
"hallucination 안 만들었는가". 이건 별도 axes (HR NLI / answer F1
/ multi-hop QA).

**framing 의무**:
- ✅ "JAMES의 time-valid retrieval 정확도가 우월"
- ✅ "JAMES의 시간-인지 검색이 다른 RAG보다 우월"
- ❌ "JAMES의 추론 성능이 우월" — LRB 측정 결과로 backed 안 됨
- ❌ "JAMES가 reasoning benchmark에서 우월" — LRB ≠ reasoning bench

**추론 성능 측정은** 별도 track (Track C — temporal reasoning bench
TimeQA / TempReason 등 외부 공개 bench + 답변 생성 + NLI scoring) 별도
cycle 필요. 본 doc 의 ⭐⭐⭐ tier 는 retrieval axis 한정.

## 1. 한 줄 요약

3-SUT × 2-scenario 측정에서 자메스 validity-window 의 **유일한
publishable contribution = time-travel retrieval**. S2 historical 쿼리
타입에서 JAMES R@1 = 0.713, Naive-supersede 0.538, Vanilla 0.225.
J-N delta = **+17.5pp** (validity-window 의 marginal 기여, measured).

gap 은 cross-scenario 에 따라 mechanism-specific 으로 발현.

## 3. Cross-scenario gap structure (publication-grade rule)

**S1 의 gap rank-order**: Vanilla < (Naive = JAMES)
**S2 의 gap rank-order (R@10)**: Naive < Vanilla < JAMES
**S2 의 gap rank-order (R@1 — UX-critical)**: Vanilla < Naive < JAMES

→ **3-tier rank-order 가 R@1 axis 에서 measured** = mother-platform 의
operational moat 의 정량 evidence.

| Mechanism | S1 contribution | S2 contribution | Publishable claim |
|---|---|---|---|
| Append-only (Vanilla) | floor | floor on R@1, accidental R@10 high on historical | "단순 보존 ≠ 시점 인지" — measured |
| Supersede-aware (Naive) | +0.022 R@10, +0.122 R@1 (on current axis) | 0 on historical R@10 (data lost), partial on mid (+0.6) | "supersede-aware = 현재 쿼리 충분, historical 불가" |
| **Validity-window (JAMES)** | **0 marginal over Naive** on S1 | **+0.225 R@10, +0.175 R@1** on S2 | **"Validity-window 의 contribution = time-travel axis"** — publishable |
