## 0. 한 줄 요약

JAMES 는 "search system" 이 아니라 "thinking system" 으로 진화한다.
기존 graph/ontology/security 코어는 그대로 유지하고, 위에 **cognitive
middleware** 를 얹어 retrieval → reflection → verification → synthesis
의 4 단계 파이프라인을 만든다. agent sprawl 없이 controlled.

---

## 1. 전략 frame (사용자 브리핑 2026-05-14)

### 1.1 강점은 보존, 약점만 채운다
현 시스템의 차별화는:
- Local-first
- Security-oriented (RBAC + ABAC + PolicyEngine + Memory Trust)
- Ontology-based graph memory (사이클 8 Knowledge Cascade 로 sources/cascade 완성)
- Auditability

**이 코어를 다시 짓지 않는다.** rebuild 는 가장 어려운 부분을 버리는
실수.

### 1.2 부족한 것
- Multi-step reasoning
- Planner / decomposer
- Reflection loop
- Verification layer
- Tool reasoning
- Working / episodic memory

현 동작:
```
question → retrieve() → answer()
```

목표 동작:
```
question
  → task decomposition
  → retrieval planning
  → multi-hop retrieval
  → hypothesis generation
  → reflection
  → verification
  → final synthesis
```

### 1.3 포지셔닝
JAMES 는 "another chatbot" 도 "another RAG wrapper" 도 아니다. 가장
방어 가능한 longterm 포지션:

> **Secure Cognitive Operating System** for organizational knowledge

다른 AI 시스템은 "instant intelligence" 를 최적화. JAMES 는 **"persistent
secure organizational cognition"** 를 최적화한다.

### 1.4 가장 강한 차별화 = security-aware reasoning
graph 관계로 보호된 정보 위에서 안전하게 추론할 수 있는 시스템은 드물다:
- prompt injection 감지
- privilege escalation reasoning
- 관계 기반 access reasoning
- contradiction detection
- data poisoning awareness
- forensic reasoning trails

`PolicyEngine` + `Memory Trust` + `sources cascade` 가 이미 기초.
cognitive middleware 가 이걸 적극 활용하면 차별화가 강해진다.

## 2.5 Hermes-style multi-agent OS 피드백 흡수 (2026-05-14 후속)

PR #275 의 초안 후, 사용자가 첨부한 Hermes 5-layer container 구조에
대해 추가 피드백. 해석 + 흡수 결과:

**Hermes 5-layer 핵심**:
```
LAYER 1  Company Brain   (vision/products, 모든 layer 가 상속)
LAYER 2  Orchestrator    (부서 선택)
LAYER 3  Department Brains (marketing/sales/ops/support)
LAYER 4  Specialized Agents (writer/critic/deploy/triage 등 ~12개)
LAYER 5  Docker isolation (1 container per agent)
```

**JAMES 정체성 유지 관점에서 4분류**:

### 🟢 흡수 (§5.7 에 반영, 본 PR)
- **Memory Scope Layering** (system / workspace / session) — §5.7.6 신설.
  Hermes 의 "context inheritance hierarchy" 가 JAMES 의 graph 와 정합
- **Roles vs workers 구분** — §5.7.3 보강. 5 agent role cap 은 concurrent
  reasoning agents 에만 적용; stateless worker function 은 무제한 허용
- **Trace replay invariant** — §5.7.2 보강. audit_bridge 만으로 결정
  rationale 완전 재구성 가능해야 (forensic reasoning 차별화)

### 🟡 보류 (§5.7.7 에 명시, v0.4 옵션)
- Container per agent / Docker isolation — RBAC/ABAC/PolicyEngine 이 이미
  더 정밀. Docker 는 v0.4 의 operator packaging 옵션 (`JAMES_WORKSPACE`
  env 위에서)
- Multi-workspace federation — v0.4 별 PR

### 🔴 거름 (적용 안 함, ARCH §5.7.5 + §5.7.6 에 명시)
- 도메인별 brain (intelligence / legal / cyber) 을 platform layer 로 박기 —
  CLAUDE.md rule #1 위반. 본 모델에서는 v1.0 이후 workspace-scoped plugin
- "one VPS = one AI company" 포지셔닝 — JAMES = cognitive infra, not
  company workflow engine
- Hermes 식 12 agent explosion — agent ≠ worker. JAMES 는 reasoning
  depth 우선, sprawl 회피가 §5.7.3 핵심 invariant

### 사용자 분석의 가치
사용자 분석이 정확히 짚은 3 약점 (orchestration 약함 / memory scope
분리 약함 / worker abstraction 약함) 은 모두 본 트랙의 4 phase 가
순차적으로 해소한다:
- orchestration → Phase 2 (Planner / Verification)
- memory scope → Phase 3 (§5.7.6 의 코드)
- worker abstraction → §5.7.3 roles-vs-workers 룰 박은 후 자연 분해

진화한다. 코어 (graph / ontology / security) 는 그대로 두고, retrieval

없으므로 슬립. CR-E 는 verification engine 과 합쳐 진행. 실제 코드
작업은 사용자 추가 피드백 후 시작.
