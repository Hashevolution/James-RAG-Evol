## 0. 한 줄 요약

JAMES 는 "search system" 이 아니라 "thinking system" 으로 진화한다.
기존 graph/ontology/security 코어는 그대로 유지하고, 위에 **cognitive
middleware** 를 얹어 retrieval → reflection → verification → synthesis
의 4 단계 파이프라인을 만든다. agent sprawl 없이 controlled.

---

## 1. 전략 frame (사용자 브리핑 2026-05-14)

### 1.1 강점은 보존, 약점만 채운다
현 시스템의 차별화는:
- Local-first
- Security-oriented (RBAC + ABAC + PolicyEngine + Memory Trust)
- Ontology-based graph memory (사이클 8 Knowledge Cascade 로 sources/cascade 완성)
- Auditability

**이 코어를 다시 짓지 않는다.** rebuild 는 가장 어려운 부분을 버리는
실수.

### 1.2 부족한 것
- Multi-step reasoning
- Planner / decomposer
- Reflection loop
- Verification layer
- Tool reasoning
- Working / episodic memory

현 동작:
```
question → retrieve() → answer()
```

목표 동작:
```
question
  → task decomposition
  → retrieval planning
  → multi-hop retrieval
  → hypothesis generation
  → reflection
  → verification
  → final synthesis
```

### 1.3 포지셔닝
JAMES 는 "another chatbot" 도 "another RAG wrapper" 도 아니다. 가장
방어 가능한 longterm 포지션:

> **Secure Cognitive Operating System** for organizational knowledge

다른 AI 시스템은 "instant intelligence" 를 최적화. JAMES 는 **"persistent
secure organizational cognition"** 를 최적화한다.

### 1.4 가장 강한 차별화 = security-aware reasoning
graph 관계로 보호된 정보 위에서 안전하게 추론할 수 있는 시스템은 드물다:
- prompt injection 감지
- privilege escalation reasoning
- 관계 기반 access reasoning
- contradiction detection
- data poisoning awareness
- forensic reasoning trails

`PolicyEngine` + `Memory Trust` + `sources cascade` 가 이미 기초.
cognitive middleware 가 이걸 적극 활용하면 차별화가 강해진다.

## 3. PR 시퀀스 (계획, 실제 작업은 추가 피드백 후)

### Phase 1 — Retrieval Intelligence (2 ~ 4 PR)
| PR | 산출물 | bench 게이트 |
|---|---|---|
| **PR-1** Reranker | `core/retrieval/rerank.py`. cross-encoder (mini ms-marco) → `retrieve_top_k → rerank → context_select` | STEP 7 graph_paths 무회귀 + precision +N% (Axis 2-A baseline 위) |
| **PR-2** Query rewriter | `core/retrieval/query_rewriter.py`. small LLM call 로 retrieval-optimized rewrite | STEP 7 무회귀 + retrieval recall +N% |
| **PR-3** (선택) Hybrid search | BM25 + vector 결합 (Whoosh / rank-bm25 추가) | retrieval 회귀 0 |
| **PR-4** (선택) Adaptive retrieval | task 복잡도 별 top_k / depth 조정 (휴리스틱) | latency 회귀 ±tolerance |

### Phase 2 — Cognitive Middleware (3 ~ 4 PR)
| PR | 산출물 | 통합 |
|---|---|---|
| **PR-5** Reflection loop | `core/reasoning/reflect.py` — draft → self_critique → revised | 기존 `core/reasoning/modes.py` 위에 layer |
| **PR-6** Verification engine | `core/reasoning/verify.py` — generator → critic → fact_checker → security_validator → final_synthesizer | **CR-E (사이클 9) 통합 — Change Request 가 verifier 의 output 을 wrap** |
| **PR-7** (선택) Planner | task decomposition (처음엔 단순 표시, 추후 본격) | 도그푸드 후 결정 |
| **PR-8** (선택) Tool router | 챗 / web search / wiki edit / graph editor 선택 | 기존 entry point 통합 |

### Phase 3 — Memory Expansion (2 ~ 3 PR)
| PR | 산출물 |
|---|---|
| **PR-9** Episodic memory | `core/memory/episodic.py` — turn 별 event log. 기존 `core/memory/store.py` 옆 |
| **PR-10** Working memory | reasoning 중 임시 state. context optimizer 의 입력 |
| **PR-11** (선택) Long-term graph evolution | entity 외 **event 노드** 추가 — 디자인 §3 graph evolution 시드 |

### Phase 4 — Controlled Multi-Agent
- 사이클 9 CR-E 가 이미 Orchestrator/Approver 구조 → 그 위에 확장
- 룰: Orchestrator + Domain Specialist + Verification Agent + Security Validator + Final Synthesizer **5 종 만**
- **agent sprawl 금지** 를 ARCHITECTURE.md 에 명시 (이번 PR 에서 추가)
