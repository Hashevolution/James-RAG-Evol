# JAMES 운영자 빠른시작 — 비개발자용 1 시간 가이드

> **대상**: 개발 지식이 없어도 회사의 정보를 안전하게 관리해야 하는 운영자.
> 법무 / 컴플라이언스 / HR / 총무 / 의료 records / 기록 담당자 등.
>
> **목표**: 1 시간 안에 5 가지 핵심 동작 (검색 / 감사 추적 / 추론 흐름 보기 /
> 변경 승인 / 시점 복원) 을 직접 수행할 수 있게 됩니다.
>
> **읽기 순서**: 위에서부터 차례대로 읽으세요. 각 시나리오마다
> "이럴 때 사용" → "단계별 절차" → "주의사항" → "더 알아보기" 순서로
> 진행됩니다.
>
> **JAMES 가 약속하는 것**: ① 모든 동작이 감사 로그에 위조 불가능하게
> 기록됨, ② 답을 모를 때는 추측하지 않고 솔직히 "정보 없음" 이라고 답함,
> ③ 잘못된 변경은 언제든 과거 시점으로 되돌릴 수 있음.

---

## 0. 시작하기 전 (5 분)

### 0.1 첫 로그인

브라우저로 회사가 제공한 JAMES 주소 (예: `https://james.example.com`)
에 접속합니다. 회사의 SSO (Single Sign-On) 가 연동되어 있다면
사원증/구글 계정으로 자동 로그인됩니다. 직접 로그인 화면이 뜨면 IT
부서에서 받은 운영자 ID + 비밀번호를 사용하세요.

### 0.2 권한 확인

화면 오른쪽 위에 "Admin" 표시가 보이면 운영자 권한이 있는 것입니다.
보이지 않으면 일반 사용자 권한이므로, IT 부서에 "운영자 권한 부여" 를
요청하세요.

### 0.3 안내 페이지로 이동

운영자 권한 확인 후, 관리자 페이지 헤더의 `📖 운영자 안내` 버튼을
누르세요. 5 단계 walk-through 가 시작됩니다 (`/onboarding`). 본 doc 의
모든 내용을 화면에서 동일하게 안내합니다. 두 가지 자료를 동시에 보면
이해가 빠릅니다.

### 0.4 모르는 용어 만났을 때

JAMES 화면 어디에서든 **점선 밑줄** 이 그어진 단어 위에 마우스를
올리면 평이한 한국어 설명이 툴팁으로 나타납니다. 깊이 알고 싶을 때는
헤더의 `📚 용어 설명` 버튼 → `/glossary` 페이지에서 26 개 용어를
카테고리별로 볼 수 있습니다 (검색 가능).

## 1. 검색 — 답 찾기 (10 분)

### 1.1 이럴 때 사용

- 사내 정책이 어떻게 되어 있는지 빠르게 확인할 때 ("우리 회사 휴가
  정책은?")
- 지난 주 보고서 요약이 필요할 때
- 누가 어떤 일을 담당하는지 빠르게 찾을 때

### 1.2 단계별 절차

1. 메인 채팅 페이지 (`/`) 로 이동합니다 (헤더의 `← 챗으로` 클릭).
2. 화면 아래 입력창에 평소처럼 한국어로 질문하세요. 예:
   - "우리 회사 출장비 정산 규정은 어떻게 되나요?"
   - "지난 분기 매출 보고서 핵심 요약해 줘"
   - "B 프로젝트 PM 이 누구지?"
3. 답이 나타나면 답 아래의 **출처 표시** (📎 아이콘 또는 문서 링크)
   를 누르세요 — 어떤 문서의 어느 부분을 사용했는지 보입니다.
4. 답에 의문이 들면 같은 질문을 약간 다르게 다시 해보세요 — 같은
   답이 나와야 정상입니다 (답이 일관성을 가져야 신뢰 가능).

### 1.3 주의사항

- **시스템이 "정보가 없습니다" 라고 답한다고 해서 정보가 없는 것은
  아닙니다.** 운영자가 해당 문서를 업로드하지 않았거나, 권한 문제로
  접근 못 했을 수 있습니다.
- **답이 너무 자신만만하면 의심하세요.** 출처 표시가 없거나, 출처가
  관련 없는 문서이면 시스템이 추측 (hallucination) 한 것입니다 — 본
  doc §3 의 "추론 흐름 보기" 로 어떻게 답이 만들어졌는지 검증할 수
  있습니다.

### 1.4 더 알아보기

- `/onboarding` 의 Step 2 (검색)
- `/glossary` 의 "RAG / Graph-RAG / Abstention / Citation /
  Hallucination" 항목
- 답을 신뢰하기 어려울 때 → §3 추론 흐름 보기

## 2. 감사 로그 보기 — 누가 무엇을 언제 바꿨나 (10 분)

### 2.1 이럴 때 사용

- 사내 문서가 어제와 다른데, 누가 언제 바꿨는지 확인할 때
- 법무 / 컴플라이언스 부서가 "지난 3 개월간 X 라는 직원의 시스템
  접근 기록 전부 제출" 을 요구할 때
- 보안 이벤트 (실패한 로그인, 비정상 접근) 를 추적할 때
- EU AI Act / GDPR / SOC 2 audit 준비

### 2.2 단계별 절차

1. 관리자 페이지 (`/admin`) → 사이드바의 **감사 로그** 메뉴 클릭.
2. 상단 필터로 좁히기:
   - **카테고리** (전체 / 사용자 활동 / 시스템 / 보안 이벤트 / 도구 호출)
   - **검색어** ("alice", "vacation_policy" 등)
   - **기간** (오늘 / 지난 7 일 / 지난 30 일)
3. 행을 클릭하면 상세 정보 (사용자, 시각, 동작 종류, IP 주소, trace_id)
   가 나타납니다.
4. CSV / PDF 로 export 가능 — 보고서 제출용으로 사용하세요.

### 2.3 주의사항

- **감사 로그는 append-only (위조 불가)** 입니다. 행 수정 / 삭제는
  설계상 불가능. 만약 누군가 "이 로그를 지워달라" 요청하면 거부해야
  하고, 그 요청 자체도 audit 됩니다.
- **법적으로 보존 의무가 있는 로그** 는 별도 백업하세요 — JAMES 의
  retention 정책 (90 일 이상은 archive) 에 따라 자동 archive 될 수
  있습니다.
- **개인정보 (PII) 가 포함된 audit 행은 마스킹** 됩니다 — 운영자가
  "raw 로그" 를 봐야 한다면 별도 권한 elevation 이 필요합니다.

### 2.4 더 알아보기

- `/onboarding` 의 Step 3 (감사 로그)
- `/glossary` 의 "Audit log / trace_id / RBAC / ABAC" 항목
- 의심스러운 행 발견 시 → §3 추론 흐름 보기

## 3. 추론 흐름 보기 — 답이 어떻게 만들어졌나 (15 분)

### 3.1 이럴 때 사용

- 답을 받았는데 의심스러울 때 ("이 답의 근거가 정말 사내 문서인가?")
- 컴플라이언스 부서가 "AI 가 어떻게 결정했는지 설명하라" 요구할 때
  (EU AI Act Art. 13 설명가능성 요구)
- 답이 일관성이 없을 때 ("어제는 A 라고 했는데 오늘은 B 라고 한 이유는?")

### 3.2 단계별 절차

1. 관리자 페이지 헤더의 `🔎 추론 흐름` 버튼 클릭 → `/admin/reasoning-flow`.
2. 두 가지 방법으로 trace 선택:
   - **오늘 최근 질문 목록** 에서 질문 본문 보고 클릭
   - 또는 **trace_id 직접 입력** (감사 로그에서 복사해 온 ID)
3. 화면 가운데에 **3-swimlane 시각화** 가 나타납니다:
   - **🔎 RETRIEVE** (보라색): 자료 찾기 — `🔐 권한확인 → 🔍 자료검색 → 🎯 재정렬`
   - **🕸️ EXPAND** (민트색): 관계 탐색 — `🕸️ 관계그래프 → 🔧 도구호출`
   - **🤖 VERIFY** (핑크색): 답변 생성 — `🤖 답변생성 → ✅ 완료`
4. 각 카드를 클릭하면 화면 아래 **단계 상세 패널** 이 열립니다:
   - 시각, 소요 시간, 찾은 자료 수, 사용 모델, 회피 여부 등
   - 각 단계가 무엇을 하는지 plain Korean 설명

### 3.3 검증 시나리오 예시

**"답이 환각인지 검증"**:
1. trace 선택 → 시각화
2. `🔍 자료 검색` 카드 클릭 → 찾은 자료 수 확인
3. 자료 수가 0 인데 답이 있다면 → **환각 가능성 높음** (시스템이
   근거 없이 추측한 답)
4. 자료 수가 충분한데도 답이 의심스러우면 → `🤖 답변 생성` 카드
   클릭 → 사용 모델, abstained (회피) 여부 확인

**"같은 질문 두 번 다른 답 인 이유"**:
1. 두 trace 의 `/admin/reasoning-flow` 비교
2. 자료 검색 단계에서 찾은 자료 수 / 출처가 다른지 확인
3. 다르면 — 그 사이에 자료 업로드 / 수정이 있었던 것 → `🕸️ 관계그래프`
   카드의 graph_paths_count 확인

### 3.4 주의사항

- **추론 흐름은 forensic evidence** 입니다. 위조 불가능 (audit 로그
  기반) 한 추론 흔적 — 법정 / 감사 보고서에 그대로 인용 가능합니다.
- **trace_id 가 없는 답** 은 시스템 외부 (LLM 직접 호출 등) 에서 나온
  답입니다 — JAMES 의 추적성을 우회한 것이므로 신뢰성이 낮습니다.

### 3.5 더 알아보기

- `/glossary` 의 "Reasoning trace / Trace ID / Hallucination / Citation /
  Path coverage" 항목
- 의심스러운 답을 발견했으면 → §5 시점 복원으로 잘못된 데이터 제거

## 4. 변경 검토 — 승인 / 거부 (10 분)

### 4.1 이럴 때 사용

- 직원이 사내 정책 문서를 수정하자고 제안했을 때
- 새 문서가 업로드되었지만 운영자 승인 전 보류 상태일 때
- AI 가 자기진화 (self-evolution) 제안을 했을 때 — 승인 필요

### 4.2 단계별 절차

1. 관리자 페이지 → 사이드바 **Change Requests** 또는 헤더의 직접 링크
   클릭. (CR.a 페이지 — PR #866)
2. **승인 대기 (Pending)** 목록에서 한 행 클릭 → 상세 modal 이 열립니다.
3. **Before / After 비교** (CR.b PR #867):
   - 왼쪽 = 현재 시스템에 있는 내용
   - 오른쪽 = 제안된 변경 (다른 부분 색상 강조)
4. **모순 중재 시각화** (CR.c PR #873): 제안이 기존 정보와 충돌하면
   4-rule decision tree 가 어떻게 결정했는지 표시.
5. 결정:
   - **승인** 버튼 → 변경 적용 + 감사 로그에 운영자 신원 (G2.a OIDC 또는
     OS 사용자 ID) 암호학적 기록 (CR.d PR #874)
   - **거부** 버튼 → 변경 폐기 + 거부 사유 입력 (직원에게 전달)

### 4.3 주의사항

- **승인 / 거부 시 운영자 신원이 위조 불가능하게 기록** 됩니다 (G2.a
  approval evidence). 나중에 "왜 승인했어?" 라고 묻기 가능합니다.
- **승인 전에 반드시 Before / After 비교 + 모순 중재 시각화 확인** —
  의도하지 않은 다른 정보 변경이 함께 포함되어 있을 수 있습니다.
- **AI 자기진화 (self-evolution) 제안은 특히 신중히** 검토하세요 — bench
  결과 + 영향 범위를 확인하고 승인하세요.

### 4.4 더 알아보기

- `/onboarding` 의 Step 4 (변경 검토)
- `/glossary` 의 "Change Request / Approval evidence / Contradiction arbiter"
  항목

## 5. 시점 복원 / 롤백 — 잘못된 변경 되돌리기 (10 분)

### 5.1 이럴 때 사용

- 어제 14 시쯤 잘못된 휴가 정책 문서가 업로드되었음을 발견
- 누군가 실수로 중요 문서를 삭제했음을 발견
- 작년 6 월 시점의 상태로 시스템 일부를 돌려놓고 싶을 때
- 컴플라이언스 부서가 "감사 시점의 시스템 상태 재현" 요구할 때

### 5.2 두 가지 모드

JAMES 는 두 가지 롤백 방식을 제공합니다:

| 모드 | 설명 | 언제 사용 |
|---|---|---|
| **최근 변경 되돌리기** | 가장 최근의 라이프사이클 이벤트 1 개를 되돌림 | 방금 들어온 변경이 잘못됐을 때 |
| **특정 시점으로 복원** | 과거 시점 T 와 현재의 차이를 계산해서 한 번에 복원 | 며칠 전 / 몇 시간 전 상태로 돌리고 싶을 때 |

### 5.3 단계별 절차

1. 관리자 페이지 헤더의 `↶ 지식 롤백` 버튼 클릭 → `/admin/knowledge-rollback`.
2. 두 flow 중 선택:

   **A. 최근 변경 되돌리기**:
   1. `↶ 최근 변경 되돌리기` 버튼 클릭
   2. 가장 최근 변경 정보가 화면에 표시 (언제 / 무슨 일 / 누가)
   3. `이 변경을 되돌리기` 클릭
   4. 확인 modal 에 **왜 되돌리는지 사유** 입력 ("어제 잘못된 정책
      문서 업로드됨")
   5. `확인 — 진행` 클릭 → 감사 로그에 의도 기록 완료

   **B. 특정 시점으로 복원**:
   1. `돌아갈 시점` 에 datetime 선택 (예: 2026-06-12 14:00)
   2. `🔍 미리보기` 클릭 → "T 이후 추가됨 / 비활성화됨 / 체인 갱신됨"
      차이 표시
   3. `이 시점으로 복원` 클릭 → 사유 입력 → 확인

### 5.4 주의사항

- **현재 v0.6 단계에서는 운영자의 롤백 "의도" 가 감사 로그에 기록됩니다**.
  그래프 상태 자체의 자동 변경은 T5.A.b lifecycle 이벤트 wiring 완료 후
  적용됩니다. 의도 기록만으로도 forensic record 로서 가치가 있습니다.
- **롤백 자체도 감사 로그에 기록** 됩니다 — "어제 14 시 상태로 되돌렸음"
  이 영구히 남습니다.
- **롤백 전 반드시 미리보기** — 의도하지 않은 다른 변경까지 함께
  되돌려질 수 있습니다.

### 5.5 더 알아보기

- `/onboarding` 의 Step 5 (시점 복원)
- `/glossary` 의 "Rollback / Replay / Time-travel / Supersede / Cascade"
  항목

## 6. 모르는 용어 만났을 때

JAMES 화면 곳곳에 점선 밑줄이 그어진 단어들이 있습니다. 그 위에
마우스를 올리면 평이한 한국어 설명이 툴팁으로 나타납니다.

전체 용어를 보고 싶을 때는:
- 관리자 페이지 헤더의 `📚 용어 설명` 클릭 → `/glossary`
- 또는 직접 URL: `https://<your-james>/glossary`
- 검색창에 한글로 입력하면 실시간 필터링됩니다 (예: "회피", "감사")

**26 개 표준 용어** 가 5 카테고리로 정리되어 있습니다:
- 🎯 **기본 개념** (RAG, Graph-RAG, Entity, Relation, Ontology, Embedding)
- 📋 **감사 + 시점** (Audit log, trace_id, Replay, Time-travel, Supersede,
  Cascade)
- ✅ **답변 품질** (Abstention, Hallucination, Citation, Path coverage)
- 🔒 **보안 + 권한** (RBAC, ABAC, OIDC, Approval evidence, CSP, Tenant)
- 🛠️ **운영자 동작** (Change Request, Rollback, Contradiction arbiter,
  Reasoning trace)

## 7. 도움이 필요할 때

### 7.1 시스템 문제 (로그인 안 됨, 답이 너무 느림, 에러 메시지)

회사의 IT 부서 (또는 JAMES 운영 담당자) 에게 문의하세요. 다음 정보를
함께 전달하면 도움이 빠릅니다:

- 어떤 페이지에서 발생했나 (URL)
- 어떤 동작을 하다가 발생했나 (단계별)
- 화면 캡처 (가능하면)
- **trace_id** — 헤더에 표시되거나 답변 옆 작은 글씨로 표시됨

### 7.2 답이 의심스러울 때

§3 추론 흐름 보기 의 단계를 따라 검증해 보세요. 그래도 환각이라고
판단되면:

1. 그 trace_id 를 메모합니다
2. 관리자 → 감사 로그 에서 그 trace_id 의 모든 행을 export
3. JAMES 운영 담당자에게 "이 trace 에서 환각 발생" 으로 신고

### 7.3 보안 사건 (의심스러운 로그인, 무단 접근)

즉시 다음 3 단계:

1. 관리자 → 감사 로그 → 카테고리 "보안 이벤트" 로 필터
2. 의심스러운 IP / 사용자 / 시각 확인
3. JAMES 운영 담당자 + 회사 보안 부서에 동시 신고

### 7.4 컴플라이언스 보고서 작성

- EU AI Act, GDPR, SOC 2 보고서에 인용할 수 있는 deterministic
  measurement evidence: `papers/rab-preprint/main.pdf` (RAB v0.1.1) +
  `papers/lrb-preprint/main.pdf` (LRB v0.2.3)
