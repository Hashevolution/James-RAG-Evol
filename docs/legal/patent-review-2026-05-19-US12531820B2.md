## 1. Patent's claimed architecture

The patent claims a pipeline with this specific shape:

```
NL query → [translate to formal query language: SPARQL / RDF / SQL]
        → query KG for relevant nodes
        → prompt LLM with KG nodes + formal query
        → LLM returns FORMAL-LANGUAGE response (e.g., triples / assignments)
        → validate accuracy of formal response (claim 1, 5)
        → convert formal response back into NL
        → return NL response via chatbot
        → update KG (add/modify/remove) using formal response
```

The "formal query language ↔ formal language response" round-trip is the
spine of all three independent claims. Claim 14 omits the explicit
"validate" step but keeps the NL→formal→NL conversion.

so the same three failing elements (b, e, g) apply across all three
independent claims.

## 3. Infringement risk assessment

### Literal infringement — **low**

A US claim is literally infringed only if **every** element is present in
the accused product. Elements (b), (e), and (g) are simultaneously absent
from JAMES, and this is not a near-miss — JAMES uses a fundamentally
different RAG architecture (dense vector retrieval + NL-only LLM I/O).

### Doctrine of equivalents — **low**

The argument "vector embeddings are equivalent to a formal query language"
faces two hard problems:

1. **Disclosure-dedication.** The patent's own specification (FIG. 2 area)
   explicitly distinguishes the two: it describes retrieval techniques as
   "keyword matching, TF-IDF (Term Frequency-Inverse Document Frequency),
   or more advanced methods like dense vector search (using models like
   BERT, Sentence Transformers, etc.)" — and then separately describes
   "SPARQL is a query language specifically designed for querying RDF
   data" as the claimed formal query language. When a patent's spec
   discloses an alternative but does not claim it, that alternative is
   dedicated to the public and cannot be recaptured under DOE.
2. **Function-Way-Result test fails on "way".** Embeddings live in a
   continuous vector space and select nodes by approximate similarity;
   SPARQL/RDF queries are discrete symbolic graph operations. Different
   way, same result is not enough.

### § 101 / Alice eligibility — **defensive card available**

In 2026-02 the Federal Circuit affirmed § 101 ineligibility of another
Amazon AI patent
([IPWatchdog](https://ipwatchdog.com/2026/02/24/federal-circuit-affirms-section-101-ineligibility-ai-patent-win-amazon/)).
This patent is built on the abstract idea of "use an LLM and a knowledge
graph to answer questions, then store the answer" with conventional
computer components and could face the same scrutiny if it were ever
asserted.

### Prior art — **invalidity card available**

The 2023-09-29 priority date does not predate Microsoft GraphRAG,
LlamaIndex Knowledge Graph indices, or LangChain graph chains. A serious
assertion could be met with invalidity defenses.

## 4. Architectural differentiators (summary)

| Axis | Amazon patent | JAMES |
|---|---|---|
| Query form | NL → SPARQL / RDF / SQL formal | NL → embedding |
| LLM output | formal language (triples / assignments) | natural language text |
| Validation | accuracy check on formal answer (claim 1, 5) | optional NL-level verifier, default off |
| KG update | auto add / modify / remove from LLM answer | `change_request.py` propose → **human approval** → merge (CLAUDE.md rule §3) |
| Deployment | cloud service provider system | local-first (CLAUDE.md §1) |
| Domain | general chatbot | platform skeleton; domain branching deferred to v1.0 |

The human-approval gate in `change_request.py` is the single most
important non-infringement feature — it converts the patent's
"auto-update" trigger into a "propose-and-review" trigger, breaking
limitation (i) on its face.

## 5. Recommendations

1. **Do not introduce a formal-query-language layer** (SPARQL, Cypher, RDF
   round-trip) into `core/retrieval/` or `core/graph/` without revisiting
   this analysis. Adding such a layer would close the gap on elements (b),
   (e), and (g) simultaneously.
2. **Preserve the human-approval gate.** Any drift toward auto-writing
   LLM answers into the KG without an `approver_username` in the audit
   log (already a CLAUDE.md §3 violation) would also close the gap on
   element (i).
3. **Track the patent family.** Add Amazon Technologies patent-family
   monitoring to `docs/LICENSE_PLAN.md` trigger list. Continuations or
   divisionals could broaden claim scope; the family number for
   US12531820B2 should be watched.
4. **Get a written FTO opinion before commercialization** in the US, KR,
   or any jurisdiction where Amazon enforces aggressively. This technical
   review is not a substitute.
