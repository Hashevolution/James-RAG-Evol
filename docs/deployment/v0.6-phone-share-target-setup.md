# 폰에서 한 탭으로 자메스에 보내기 — Share Target / Shortcuts Setup

> **Status**: 운영자 dogfooding 첫날 runbook. 자메스 server 측 코드
> 변경 없음 — 기존 `POST /upload/` endpoint 를 폰의 "공유" 시트에서
> 한 번에 호출하도록 폰 측만 설정. 약 5-10 분.
>
> **목표**: 폰으로 자료/문서 사진을 찍거나 PDF / 메모를 받고, 그
> 자리에서 **공유 → JAMES** 한 탭으로 자메스 wiki + chroma 인덱싱
> 까지 보냄. dogfooding 첫날의 "폰 → 자료화" 첫 갭을 mechanical 로
> 메움.
>
> **Audience**: 본인 (Hashevolution) + 자기 폰. 외부 customer 가
> 아니라 본인 폰을 본인 자메스 서버에 연결하는 시나리오.

## 1. 사전 조건 (3 분)

### 1.1 자메스 서버 URL 결정

| 시나리오 | 추천 URL 모양 |
|---|---|
| 폰과 PC 가 같은 Wi-Fi | `http://192.168.x.x:8000` — PC 의 LAN IP. `ipconfig` (Win) / `ifconfig` (macOS) 로 확인 |
| 외출 중에도 사용 | **Tailscale** 추천 (`https://james-pc.tailnet-name.ts.net:8000`). Cloudflare Tunnel / ngrok 도 가능. **plain ngrok 은 TLS 인증서 + URL 변동 위험** |
| HTTPS 권장 | P1.1 `docs/deployment/v0.6-https-production.md` 따라 self-signed 또는 Let's Encrypt 적용. iOS Shortcuts 는 self-signed 신뢰 안 함 — Tailscale 의 자동 mTLS 또는 정식 HTTPS 권장 |

폰의 브라우저에서 위 URL 에 한 번 접속해서 자메스 로그인 페이지가
뜨는지 먼저 확인. 안 뜨면 Shortcut 도 안 됨.

### 1.2 API key 확보

자메스 admin 페이지 또는 본인 계정의 API key 를 미리 복사해둠.
JWT 만료가 있으므로 **API key** 가 영구. POST `/upload/` 의 form
field `api_key` 에 들어감.

⚠️ Shortcut 안에 API key 가 plain text 로 저장됨. **본인 폰에서만**
유효한 전제.

## 2. iOS — Shortcuts 앱으로 만들기 (~3 분)

### 2.1 새 Shortcut 만들기

1. **Shortcuts** 앱 → 우측 상단 **+** → 새 단축어
2. 이름: `JAMES 에 보내기`
3. 우측 상단 ⓘ → **공유 시트에 표시** 켬 → 받는 형식: **이미지, 미디어, 파일, URL, 텍스트** 모두 체크

### 2.2 액션 추가

순서대로:

| # | 액션 | 설정 |
|---|---|---|
| 1 | **URL** | `https://YOUR-JAMES-URL:8000/upload/` (1.1 에서 결정한 URL) |
| 2 | **URL의 콘텐츠 가져오기** | 메서드: **POST** / 요청 본문: **양식** / 양식 필드 4개:<br>• `file` = 파일 (변수: **단축어 입력**)<br>• `api_key` = 텍스트 (위 1.2 의 키)<br>• `source_type` = 텍스트 `prod`<br>• `instruction` = 텍스트 (선택 — 예: `폰 캡처 / 회의 메모`) |
| 3 | **알림 표시** | 메시지: **URL의 콘텐츠 가져오기 결과** (변수 선택). 업로드 성공 / category / summary 가 뜸 |

저장 → 끝.

### 2.3 사용

폰 어디서나 (사진앱 / 카메라 / 파일앱 / 메모) → **공유** 시트 →
`JAMES 에 보내기`. 알림으로 처리 결과 (`status`, `category`,
`summary`) 가 뜨면 성공.

## 3. Android — HTTP Shortcuts 앱 (~3 분)

iOS 의 Shortcuts 와 동등한 가장 가벼운 path. F-Droid / Play Store
의 **HTTP Shortcuts** (rmy.ch, open-source, 무료).

### 3.1 새 Shortcut 만들기

1. HTTP Shortcuts 앱 → **+** → **Regular HTTP Shortcut**
2. 이름: `JAMES 에 보내기`
3. **Basic Request Settings**:
   - Method: `POST`
   - URL: `https://YOUR-JAMES-URL:8000/upload/`
4. **Request Body** → **Form Data (multipart)**:

   | Key | Value Type | Value |
   |---|---|---|
   | `file` | File | (Sharing: "Shared File" 선택) |
   | `api_key` | Static | (1.2 의 키) |
   | `source_type` | Static | `prod` |
   | `instruction` | Static | 비워두거나 `폰 캡처` |

5. **Trigger and Execution Settings**:
   - **Settings** → "Add to share menu" 켬
6. 저장.

### 3.2 사용

폰 갤러리 / 카메라 / 파일 / Drive → **공유** → `HTTP Shortcuts` →
`JAMES 에 보내기`. response toast 가 뜸.

### 3.3 대안 — PWA share_target (가벼움)

자메스 frontend 가 PWA 화 되면 `manifest.json` 의 `share_target`
필드를 통해 Android 공유 시트에 자메스 자체가 직접 나타남. **이 가이드
이후 step ② PWA 화** 의 자연스러운 다음 단계. 본 가이드의 HTTP Shortcuts
는 PWA 화 전까지의 bridge.

## 4. 동작 검증 (1 분)

1. 폰 카메라로 아무 문서 (책 한 페이지 / 영수증 / 화이트보드 등) 촬영
2. 공유 → `JAMES 에 보내기`
3. 5-30 초 후 (서버 워크스페이스 크기에 의존, agent 보고: 110-197s
   가능) 응답 알림 확인
4. PC 브라우저로 자메스 워크스페이스 → 검색에 방금 찍은 자료의 핵심어
   입력 → 자료가 검색되면 성공

## 5. 트러블슈팅

| 증상 | 원인 가능성 | 해결 |
|---|---|---|
| 401 (인증 실패) | `api_key` 오타 또는 만료 | 자메스 admin 에서 키 재발급 후 Shortcut 의 값 갱신 |
| 403 | role 에 `upload.file` feature 없음 | admin 으로 본인 계정 role 확인 |
| 네트워크 연결 안 됨 | LAN IP 가 변동 (DHCP) / 외출 중 | 1.1 의 Tailscale 도입 권장 |
| TLS 인증서 신뢰 안 됨 (iOS) | self-signed 또는 ngrok 임시 cert | Tailscale 또는 Let's Encrypt 로 정식 cert |
| 알림에 JSON 그대로 뜸 | iOS 의 "알림 표시" 가 dict 그대로 stringify | Shortcuts 의 **사전에서 값 가져오기** 액션으로 `status`/`summary` 추출 후 표시 |
| 큰 사진 (10-15MB) 너무 느림 | 클라이언트 측 리사이징 없음 — agent 보고의 mechanical 갭 | 본인이 첫 dogfooding 후 짜증 정도 따라 후속 PR 로 client resize |

## 6. 다음 step ladder (이 setup 이후)

이 가이드는 직전 대화의 step ladder ① 단계. 본인이 1-2 주 dogfooding
후 다음 결정:

- **유지** — Shortcuts 만으로 충분하면 그대로
- **② PWA 화** — 자메스 frontend 에 `manifest.json` + service worker
  추가, 홈 화면 아이콘. share_target manifest field 로 Android 공유
  시트에 자메스가 자체 등장. ~1-2일 작업
- **③ React Native / Flutter 네이티브** — 위 둘로 어디가 막히는지
  본인이 1-2 개월 dogfooding 후 결정. 미리 짓는 건 forced-discovery
  함정
