## 2. 4 벤치 정밀화

### 2.1 RGB (Retrieval-Augmented Generation Benchmark) — Abstention 외부 검증

**Source**: Chen et al. 2024 EMNLP, `arXiv:2309.01431`

**구조**:
- Information retrieval + Generation 측정
- 4 axis: Noise robustness / Negative rejection / Information integration / Counterfactual robustness
- **Negative rejection ≈ JAMES abstention F1** 직접 매치

**Fixture**:
- ~600 questions (English + Chinese)
- Multi-document context (3-5 documents per question)
- gold answer + abstention label

**JAMES 측정 환경**:
- production Default (advanced 스택 ON)
- AnswerStyleClassifier auto-mount
- 답 형식 = first line ANSWER:

**측정 metric**:
- Negative rejection accuracy (JAMES abstention F1 ↔ RGB negative rejection)
- Noise robustness (citation 강건성)

**Cost**:
- ~600 query × 양 모델 = 1200 queries
- e4b ~35s + advanced ON 60% overhead = ~55s → ~10h
- mixtral ~75s + overhead = ~120s → ~20h
- 총 ~30h CPU

**Value tier**: ⭐⭐⭐ (JAMES-unique 강점 + 외부 evidence + Track A 권고)

### 2.2 ALCE (Automatic LLM Citation Evaluation) — Citation 외부 검증

**Source**: Gao et al. 2023, `arXiv:2305.14627`

**구조**:
- 3 fixtures: ASQA / QAMPARI / ELI5
- Citation precision / recall 자동 채점
- Long-form generation + entity-grounded citations

**Fixture**:
- ASQA: ~948 questions (long-form QA with multi-document evidence)
- QAMPARI: ~1000 questions (list-based answers)
- ELI5: ~1000 questions (long explanation)

**JAMES 측정 환경**:
- production Default + AnswerStyleClassifier auto-mount
- citation 메커니즘 = `core/reasoning/pipeline.py:343` `sources: docs[:3]`
- response_style = "natural" (long-form, ALCE 자동 분류)

**측정 metric**:
- Citation precision (% 답 안 citation 이 정답 source 인지)
- Citation recall (% 정답 source 가 답 안 cited 인지)

**Cost**:
- ALCE 권장 = ASQA + QAMPARI 우선 (~2000 query × 양 모델 = 4000)
- e4b ~35s × 0.6 (no advanced) = ~12-18h
- mixtral ~75s × 0.6 = ~30-40h
- 총 ~50h CPU
- **smoke option**: n=200 sample × 양 모델 = ~5-7h

**Value tier**: ⭐⭐⭐ (JAMES citation 외부 evidence + ALCE = de facto citation standard)

### 2.3 MuSiQue (Multi-step QA) — Graph-RAG 외부 검증

**Source**: Trivedi et al. 2022, `arXiv:2108.00573`

**구조**:
- 2-hop / 3-hop / 4-hop questions
- Wikipedia paragraphs as context
- Decomposed reasoning chain

**Fixture**:
- Train ~25K, Dev ~2.5K
- 측정 권장: Dev sample n=500-1000

**JAMES 측정 환경**:
- production Default + advanced 스택 ON (planner 가 multi-hop 분해)
- graph-RAG path coverage (DFS + ACT)

**측정 metric**:
- EM (exact match)
- F1 (partial match)
- Support fact accuracy (path coverage 외부 정합)

**Cost**:
- n=500 × 양 모델 = 1000 queries
- e4b ~55s = ~8-10h
- mixtral ~120s = ~17-20h
- 총 ~30h CPU

**Value tier**: ⭐⭐ (MultiHop-RAG 와 같은 type 이라 cross-bench 정합 evidence)

### 2.4 2WikiMultiHopQA — Multi-hop Cross-bench Confirm

**Source**: Ho et al. 2020, `arXiv:2011.01060`

**구조**:
- 2-hop questions
- Wikipedia paragraph evidence
- Comparison / inference / bridge question types

**Fixture**:
- Train ~167K, Dev ~12K
- 측정 권장: Dev sample n=500

**JAMES 측정 환경**:
- production Default + advanced 스택 ON
- comparison/inference query type 와 JAMES 의 4 question_type fixture 정합

**측정 metric**:
- EM / F1
- Support fact accuracy

**Cost**:
- n=500 × 양 모델 = 1000 queries
- ~30h CPU 양 모델 통합

**Value tier**: ⭐⭐ (multi-hop cross-bench 정합 + Multi-bench Δ evidence)
