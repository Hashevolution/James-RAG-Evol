# v0.6.2 — IRA: Inference Replay Audit (설계 메모, design-stage)

> **Status**: design-stage. 구현 PR 없음. 이 메모는 "SEKOS를 AI 추론
> 감사(audit) 플랫폼으로 확장할 수 있는가"에 대한 **자산 실사 + 결손
> 목록 + 단계 계획**이다.
>
> **운영자 결정 3건** (2026-09-03, 이 메모의 전제):
> 1. **감사 범위 = 외부 모델 포함** — 남의 스택(OpenAI / Claude /
>    LangChain / 자체 RAG)이 남긴 로그를 import 해서 SEKOS가 감사한다.
> 2. **리플레이 = 반사실(counterfactual)** — 같은 질문·같은 증거를
>    다른 모델/다른 설정에 재투입해 대조한다. (재구성은 그 전제 계층,
>    재실행은 그 부분집합.)
> 3. **원문 저장 = 워크스페이스별 옵션** — 기본은 해시+요약, 감사가
>    필요한 워크스페이스만 프롬프트·증거 원문 보존을 켠다.
>
> **결론 요약**: 가능하다. 그리고 **네 계층 중 두 계층이 이미 서 있다**.
> 새로 지어야 하는 것은 (a) 실 토큰 계측, (b) 재대입용 원문 페이로드
> 저장소, (c) 외부 로그 import 격리 존 — 이 셋이다. 나머지는 기존
> 자산의 승격(promotion)이다.

## 1. 이미 서 있는 것 (자산 실사)

이 프로젝트는 "감사 가능한 RAG"를 목표로 3개 사이클을 돌았기 때문에,
요청된 시스템의 **골격이 이미 존재한다**. 새로 설계할 필요가 없는 부분:

| 요청 항목 | 이미 있는 자산 | 위치 |
|---|---|---|
| 추론 단계 기록 | `TraceStep` frozen schema — `stage / backend_id / parent_step_id / inputs_hash / output_summary / applied_rule / latency_ms / error` (7 stage whitelist) | `core/reasoning/trace_schema.py` |
| "audit만으로 재생 가능" 불변식 | ARCHITECTURE §5.7.2 trace-replay invariant — *ephemeral 메모리 상태가 결정 근거를 들고 있으면 안 된다* | `docs/ARCHITECTURE.md` §5.7.2 |
| 단일 질의 재생 CLI | `replay_trace.py <trace_id>` — audit_log에서 추론 시퀀스 복원 | `scripts/replay_trace.py` |
| 시점 상태 복원 | `reconstruct_graph_at(t)` — 로그 스트림만으로 t 시점 그래프 재구성 | `core/lifecycle/replay_graph/` |
| 운영자 API | `GET /admin/trace/{trace_id}`, `/admin/audit/recent-traces`, replay-at 엔드포인트 | `routes/admin.py:713, 1126, 1626` |
| 감사 UI 표면 | 추론 흐름 뷰 + 타임트래블 뷰 | `frontend/static/reasoning-flow.js`, `time-travel.js` |
| **감사 품질의 척도** | **RAB v0.1.1 (FROZEN)** — AC(완전성) / RF(재생 충실도) / PC(출처 커버리지), EU AI Act Art. 10/12/19 앵커, LLM judge 없는 결정적 지표 | `eval/rab/SPEC-v0.1.md` |
| **외부 시스템 감사 인터페이스** | **RAB SPEC §1 추상 감사로그 계약** — SUT는 JSONL 한 줄=한 이벤트로 export 하면 채점 가능. 자체 이벤트 어휘는 **mapping table**로 canonical 10종에 사상 | `eval/rab/SPEC-v0.1.md` §1, `eval/rab/driver.py` |
| **외부 관측 표준 사상표** | **OTel GenAI semconv → RAB canonical** 매핑 (해시 핀) | `eval/rab/mappings/otel_genai_to_rab.json` |
| 비용 환산 | 모델별 USD/1M-token 요율표 + 월별 tally + cap | `core/routing/cost_cap.py::estimate_usd` |
| PII 탐지 | `detect_pii` / `check_query_privacy` (RRN·전화·이메일·카드) | `core/routing/privacy.py` |
| 보존기간 정책 | retention class 메타데이터 + `pending_retention_review` (자동삭제 없음) | `core/lifecycle/retention.py` |
| 테넌트 격리 | `current_tenant_id()` ContextVar + 감사행 테넌트 스코프 | `core/lifecycle/tenant.py` |

**핵심 인식**: RAB SPEC §1은 이미 *"SUT의 native 이벤트 어휘를 mapping
table로 canonical 타입에 사상한다"*고 frozen 되어 있다. 즉 **외부 모델
로그를 받아들이는 계약이 이미 동결된 형태로 존재**한다. Baseline-1
어댑터가 OTel-shape span을 채점한 선례도 있다. 요청하신 "외부 AI 결과를
감사한다"는 새 인터페이스 설계가 아니라 **기존 벤치 인터페이스를 제품
경로로 승격시키는 일**이다.

## 2. 실제로 비어 있는 것 (검증된 결손 4건)

### 결손 1 — 실 토큰이 계측되지 않는다 (가장 치명적, 가장 싸다)

요청의 "토큰이 얼마나 쓰이고"는 **지금 답할 수 없다**.

- `core/gemma_client/client.py:291-292` 는 Ollama 응답에서
  `resp.json().get("response")` 만 읽는다. 같은 응답이 들고 오는
  `eval_count` / `prompt_eval_count` (실 출력·입력 토큰 수)는 **버려진다**.
- `eval/qvt/oracle.py:850` 에 이 사실이 주석으로 명시돼 있다 —
  *"A future PR can wire Ollama eval_count through the server response."*
- 그래서 QVT의 `token_cost` 축은 **answer_chars 프록시**이고
  (`oracle.py:860`), LRB scorer는 **ctx/4 근사**를 쓴다
  (`eval/external/lrb/scorer.py:73`).
- `cost_cap.estimate_usd(input_tokens, output_tokens)` 는 준비돼 있으나
  **먹일 실수치가 없다**.

즉 비용 계층은 지붕만 있고 계량기가 없다. 이건 PR 1~2개짜리 작업이다.

### 결손 2 — 재대입할 원문이 저장되지 않는다

반사실 리플레이(운영자 결정 #2)의 전제가 지금 깨져 있다.

- `compute_inputs_hash()` 는 sha256(system+prompt)의 **앞 16자만** 남긴다.
  "같은 입력인데 다른 결과"는 탐지 가능하지만, **그 입력을 다시 만들 수는
  없다** (해시는 역함수가 없다).
- `truncate_summary()` 는 출력을 **200자에서 자른다**.
- 관측 JSONL(`log_stage`)은 질문 텍스트를 **200자 캡**으로,
  검색 점수·엔티티 id는 남기지만 (`core/reasoning/pipeline_loops.py:242`,
  `:300`) **검색된 문서 본문도, 합성 프롬프트도 남기지 않는다** —
  주석에 *"Observability-only; nothing reads it back into the answer
  path"* 라고 명시돼 있다.

따라서 "저장된 (질문 + 증거집합 + 파라미터)를 다른 모델에 재투입"은
**저장 계층이 없어서 불가능**하다. 이것이 운영자 결정 #3이 필요했던 이유다.

### 결손 3 — 외부 로그를 받아들일 제품 경로가 없다

RAB의 외부 인터페이스는 **벤치마크 하니스 안에만** 있다. `driver.py`는
시나리오를 SUT에 *실행*시키는 구조(어댑터가 `ingest/query/snapshot`을
가진 살아있는 시스템이어야 함)이고, Baseline-1은 OTel-shape span을
**인프로세스에서 생성**한다. **"이미 끝난 남의 로그 파일을 받아
채점한다"** 는 진입점 — importer, mapping-table 등록소, 격리 저장소,
스코어카드 API — 이 없다.

### 결손 4 — "왜 그렇게 나왔는가"의 층위가 정의되지 않았다

현재 답할 수 있는 것은 `applied_rule` + `output_summary(200자)` +
`inputs_hash` 수준, 즉 **결정 수준(decision-level)** 뿐이다. 이건 결손이라기
보다 **정직한 범위 선언이 없다**는 문제다 — §5에서 3층으로 못박는다.

## 3. 목표 아키텍처 — 4계층

```
L3  반사실 실행   같은 질문·같은 증거를 다른 모델/설정에 재투입 → 대조 리포트
     (P4)         └ 선행: L1
L2  재구성 뷰     로그만으로 질문→검색→추론→답변 + 토큰·비용을 화면에 복원
     (P2)         └ 선행: L0. 외부 로그도 같은 뷰에 태움 (P3)
L1  원문 페이로드  프롬프트·증거·파라미터 원문 보존 (워크스페이스 opt-in,
     (P1)         PII 마스킹, retention class) — 새 trust zone §5.7.16
L0  실 계측       eval_count/prompt_eval_count·provider usage → TraceStep
     (P0)         extras → cost_cap tally. 프록시(문자수) 폐기.
────────────────────────────────────────────────────────────────
IN  외부 로그 import (P3): JSONL + mapping table → 격리 존 →
     AC/RF/PC 스코어카드 (EU AI Act Art. 10/12/19 사상, 기존 RAB 재사용)
```

### LOCK 1 — TraceStep 스키마는 건드리지 않는다

ARCHITECTURE §5.7.2 는 *"새 백엔드는 registry만 확장, schema는 확장
안 함 — replay 도구는 transport와 무관하게 한 가지 row 형태만 읽는다"*
로 동결돼 있다. 토큰 수치는 **`emit_trace_step(extras=...)`** 로 흘린다
(`audit_bridge._resolve_answer` 가 non-reserved key를 `answer` JSON에
접어 넣는 기존 경로). 6-필드 계약은 그대로, replay 도구는 무변경.
→ 스키마 변경 PR과 architecture 라벨이 **불필요**해진다.

### LOCK 2 — 원문은 audit_log에 넣지 않는다

audit_log는 append-only이고 삭제 경로가 change-request 승인 플로우
하나뿐이다(`retention.py` 설계 의도). 프롬프트·증거 원문을 여기 넣으면
**삭제 불가능한 PII 저장소**가 된다. 원문은 **별도 payload store**
(trace_id 참조, 자체 보존기간, 워크스페이스별 on/off, 마스킹 후 저장)에
둔다. audit_log에는 payload 참조 id와 해시만 남는다 → 감사 불변식은
유지되고, GDPR 삭제 요구는 payload store에서만 처리된다.

### LOCK 3 — 외부 import 로그는 격리(quarantine)한다

import된 남의 로그는 **untrusted external data**다. 채점·표시 대상일 뿐
**지식그래프에 ingest 되지 않고, 프롬프트로 들어가지 않는다**. 별도
네임스페이스 + 읽기 전용. (프롬프트 인젝션 표면을 원천 차단.)

## 4. 토큰 회계 — 정직한 범위

- **로컬(Ollama)**: `eval_count`(출력) / `prompt_eval_count`(입력) 그대로.
  실측치다.
- **클라우드(Anthropic/OpenAI 등)**: 각 provider의 usage 필드를 그대로
  기록. 요율은 `cost_cap._RATES` 표.
- **외부 import 로그**: 남이 기록한 값을 **그대로 전재**하고 출처를 표시한다.
  없으면 없다고 표시한다 — 추정치로 채우지 않는다.
- **금지**: provider 간 토큰 수를 합산·평균내어 단일 지표로 발표하는 것.
  토크나이저가 다르므로 등가가 아니다. **provider별로 분리 보고**한다.
  (`feedback_finding_size_honest_framing` 적용.)
- 부수효과: L0가 서면 QVT `token_cost` 축의 문자수 프록시를 실측으로
  교체할 수 있다 — 다만 **기존 측정 결과와의 비교 가능성이 끊긴다**.
  프록시 축은 병기 유지하고, 실측 축은 새 축으로 추가한다.

## 5. "왜 그렇게 나왔는가" — 3층 정직 구분

이 시스템이 답할 수 있는 것과 없는 것을 미리 못박는다. (α 사이클의
과대 framing 사고를 반복하지 않기 위한 장치.)

| 층 | 내용 | 결정성 | 채택 |
|---|---|---|---|
| **W1 결정 수준** | 어떤 문서가 왜 선택됐나(점수·랭크), 어떤 규칙이 적용됐나(`applied_rule`), 어떤 라우팅·백엔드·파라미터였나, 어떤 게이트가 걸렸나(abstention/privacy/cost cap), 토큰·비용이 얼마였나 | **완전 결정적**. 로그만으로 재현 | ✅ **제품의 본체** |
| **W2 모델 자기서술** | 모델이 낸 CoT / reasoning 텍스트를 기록·표시 | 기록은 결정적이나 **자기서술은 실제 인과의 증거가 아니다** (post-hoc rationalization) | ⚠️ **기록·표시하되 "모델의 주장"으로 라벨링**. 설명으로 승격 금지 |
| **W3 기계적 해석** | attention/attribution 수준의 "왜" | 로컬 오픈웨이트에서만 가능, 상용 API는 원리적으로 불가 | ❌ **non-goal** |

**반사실(L3)이 주는 "왜"는 W1의 확장이지 W2/W3가 아니다.** "증거를 뺐더니
답이 바뀌었다 / 모델 B는 다르게 답했다"는 **대조적 사실**이며, 이것이
실무 감사에서 가장 쓸모 있는 형태다.

**반사실의 필수 캐비어트**: LLM은 비결정적이다(temperature, 모델 버전
드리프트, 서빙 스택). 따라서 재실행 결과가 원본과 다른 것은 **결함의
증거가 아니다**. L3 리포트는 반드시 (a) n>1 반복, (b) 원본-모델 자기
재실행(self-baseline)을 대조군으로 함께 싣는다. self-baseline 없이
"모델 A vs 모델 B" 만 보여주는 리포트는 **금지**한다. (α-8 페어링 교훈:
n=1의 겉보기 차이가 n=3에서 소멸한 사례.)

## 9. Non-goals

- 기계적 해석가능성(W3) — attention/attribution.
- 모델 자기서술을 인과 설명으로 승격하는 것(W2 → W1 격상).
- 규제 준수 인증. IRA는 **감사 가능성의 측정**이지 적합성 판정이 아니다.
- 외부 로그의 자동 지식그래프 편입.
- LLM judge 기반 "추론 품질 점수". RAB의 결정적-지표 원칙을 깨지 않는다.
