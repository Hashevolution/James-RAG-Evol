# Cycle γ — Bench #5 Candidate: Lean 정형증명 (T1-b lemma DAG → T2-1 pass@k 합성) — Design Memo

> Cycle γ 의 4 외부 벤치 (RGB + ALCE + MuSiQue + 2WikiMultiHopQA)
> 에 이어, **5번째 벤치 후보**로서 Lean 정형증명 트랙의 design memo.
> 수학을 제품 vertical 이 아니라 **외부 측정 fixture** 로, Lean 을
> **외부 trust-zone 검증기** 로 취급한다 (cycle γ 가 RAG 벤치를
> 다루는 방식과 동일 → mother-platform 룰 무충돌).
>
> 진입은 cycle γ 4 벤치 + v0.4.2 T5 (Replayable Audit Graph full)
> 뒤로 게이트됨 (§9).

## 0. TL;DR

cycle γ 4 벤치는 전부 RAG/QA 계열 — **추론 ceiling 이 실제로
드러나는 도메인이 아니다** (Direction α 가 뉴스-RAG fixture 에서
local 9/9 = cloud 9/9 로 끝난 바로 그 이유). Lean 정형증명은:

1. **leak 면역 + self-eval 면역**: Lean kernel 이 oracle. 증명항은
   compile 되거나 안 되거나 — 학습-지식 leak 가 *유효한 증명을
   위조할 수 없다* (Direction α Stage 4b 를 죽인 학습-leak 의
   구조적 면역). JAMES 가 자기 fixture+자기 oracle 로 자기 답을
   채점하는 self-eval 함정 (cycle β #3 skip) 도 구조적으로 회피.
2. **JAMES 검색 강점이 진짜 병목에 닿음**: 정형증명의 실제 병목 =
   "관련 Mathlib lemma 회수". 이건 retrieval + graph-RAG 가 marginal
   contribution 을 *측정가능하게* 가질 수 있는 자리.
3. **재현가능 감사 = 차별점**: `Lean 증명항 + 그걸 만든 추론 trace`
   = T5 Replayable Audit Graph 비전 그 자체.

**합성 구조 (사용자 결정 2026-06-06)**: T1-b (lemma 의존 DAG 재구성,
oracle = Mathlib 실제 import 그래프 = 청정 측정) 를 **하위 컴포넌트
겸 warmup** 으로 깔고, 그 위에서 T2-1 (Lean pass@k) 를 올린다.
T1-b 가 곧 T2-1 의 **A축 (JAMES 기여 귀속) ablation 근거**가 된다.

## 1. Why — cycle γ 4 벤치가 못 닿는 gap

### 1.1 추론 ceiling 도메인 gap

| 측정 시도 | 결과 | 죽은 이유 |
|---|---|---|
| Direction α v2 reasoning-isolated | local 9/9 = cloud 9/9 | RAG QA = 추론 ceiling 안 드러남 |
| Direction α Stage 4b cloud raw | **invalid** | Claude 학습-leak (multihop=2023 뉴스) |
| cycle γ RGB/ALCE/MuSiQue/2Wiki | (예정) | 전부 RAG/QA 계열, 같은 한계 |

→ **추론이 진짜로 중요한 + 학습-leak 면역인 도메인** 이 측정
포트폴리오에 0 개. Lean 정형증명이 그 칸을 채운다.

### 1.2 cycle γ 외부 검증 매트릭스에 한 행 추가

## 2. 합성 구조 — T1-b → T2-1

```
[T1-b]  질문: "정리 X 를 증명하는 데 필요한 Mathlib lemma 집합/의존은?"
        JAMES graph-RAG (DFS+ACT) → lemma 의존 DAG 재구성
        oracle = Mathlib 실제 import/dependency 그래프 (위조 불가, mechanical)
        metric = lemma-set Recall@k / 의존-edge F1 / EM
        역할 = retrieval+graph 기여의 청정 정량 (모든 위험축 ✅)
                              │
                              ▼  (회수된 lemma 가 입력)
[T2-1]  목표: 정리 X 의 Lean 증명항 생성
        JAMES retrieval (T1-b 회수 lemma) → Claude tactic 초안 → Lean 검증
        oracle = Lean kernel (위조 불가, proof-theoretic)
        metric = pass@k (k=1,8,32)
        역할 = leak/self-eval 면역 추론 ceiling 측정 + JAMES 기여 ablation
```

핵심: T1-b 와 T2-1 은 경쟁이 아니라 **파이프라인의 두 단계**.
T1-b 의 lemma 회수 품질이 T2-1 의 ablation ON 조건을 정의한다.

## 3. 벤치 정밀화

### 3.1 T1-b — Mathlib import/dependency DAG 재구성

- **Source**: Mathlib4 (live, `leanprover-community/mathlib4`)
- **Fixture**: Mathlib 정리 N 개 (n=500 권장) + 각 정리의 실제 의존
  lemma 집합 (Lean 의 `#print axioms` / 의존 추출로 ground truth 생성)
- **oracle**: Mathlib 실제 import/dependency 그래프 — **내장, mechanical,
  exact**. self-eval 불가, leak 무관 (구조 정합은 모델이 알아도 채점
  무관).
- **metric**: lemma-set Recall@k, 의존-edge F1, EM
- **JAMES 환경**: graph-RAG (DFS+ACT) + entity-anchor 확장
- **value tier**: ⭐⭐⭐ (모든 위험축 청정 + T2-1 의 A축 근거)

### 3.2 T2-1 — Lean pass@k (miniF2F / ProofNet / PutnamBench)

| 벤치 | source | 규모 | 성격 |
|---|---|---|---|
| miniF2F | `arXiv:2109.00110` | 488 (valid+test) | 올림피아드/대수, 표준 |
| ProofNet | `arXiv:2302.12433` | 371 | 학부 수학 (해석/대수) |
| PutnamBench | `arXiv:2407.11214` | ~640 | Putnam, 미해결 다수 (leak 면역 강) |

- **oracle**: Lean kernel — **위조 불가 (proof-theoretic)**. 가장 강한
  oracle. informal 답이 학습 분포에 있어도 *유효한 Lean 증명항*은
  fake 불가.
- **metric**: pass@k (k=1, 8, 32), 증명 길이, tactic 수
- **JAMES 환경**: T1-b 회수 lemma 주입 (ON) vs 미주입 (OFF) = ablation
- **value tier**: ⭐⭐⭐ (추론 ceiling leak-immune 측정 + 진짜 프런티어)

## 4. 위험 매트릭스 (Direction α 사후 룰 채점)

축: L=leak 면역 / S=self-eval 면역 / O=oracle 강도 / A=JAMES 기여
귀속 / N=n=1 inflation 저항 / H=정직 framing 노출 (높을수록 안전).

| 후보 | L | S | O | A | N | H |
|---|:--:|:--:|:--:|:--:|:--:|:--:|
| **T1-b lemma 의존 DAG** | ✅ | ✅✅ | ✅✅ | ✅ | ✅ | ✅ |
| **T2-1 Lean pass@k** | ✅✅ | ✅✅ | ✅✅✅ | ⚠️→✅ | ✅ | ✅ |

**A 약점 해소**: T2-1 의 유일한 약점 = "JAMES retrieval 이 Claude
단독보다 나았나?" 귀속성. 이건 **T1-b ablation (회수 lemma ON/OFF
pass@k 차이)** 로 ⚠️→✅. §5 Phase C 가 이 ablation 을 의무화한다.

**폐기된 인접 후보** (이 매트릭스로 REJECT):
- FrontierMath/Putnam **informal** cloud-tier fixture: L=❌❌ (Direction
  α Stage 4b 학습-leak 1:1 재현). Lean-formal 변환만 생존 = T2-1 로
  흡수.
- Millennium sub-target: H=❌ ("리만에 손댔다" 파국적 over-claim),
  A=❌ (JAMES 기여 거의 0).

## 6. A축 ablation 설계 (이 트랙의 crux)

T2-1 이 mother-platform 가치 evidence 가 되려면 "Claude 가 잘한 것"이
아니라 "**JAMES 가 회수해서** 잘한 것"을 분리해야 한다.

```
Δ_JAMES = pass@k[retrieval ON, T1-b lemma 주입]
        − pass@k[retrieval OFF, Claude 단독]
```

- Δ > 0 + n=3 paired 유의 → JAMES retrieval 의 정형증명 marginal
  contribution **입증** (mother-platform 가치, leak-immune oracle 위에서)
- Δ ≈ 0 → "Claude 가 이미 lemma 를 안다" = JAMES 기여 미입증 (정직
  framing: 이 도메인에선 retrieval 무가치 — Direction α 와 같은 정직
  null 결과, 단 이번엔 oracle 이 hard 라 결과 자체는 valid)

→ **어느 쪽이든 valid evidence**. Direction α 와 달리 oracle 이
위조 불가라 null 도 신뢰 가능. 이게 이 트랙의 핵심 강점.

## 8. 거버넌스 — 수학 = fixture, vertical 아님

**CLAUDE.md 룰 #1 (v1.0 까지 도메인 분화 금지) 무충돌 근거**:

- 수학을 **제품 vertical** 으로 만들면 위반. 본 트랙은 **측정
  fixture** + Lean **외부 검증 도구** → cycle γ 가 RAG 벤치를 다루는
  방식과 **동일 구조**.
- 새 `core/` 도메인 모듈 0 개. 모든 작업 = `eval/external/` (측정
  하니스) + `scripts/research/` (러너). core retrieval/graph/reasoning
  은 **수정 없이 측정 대상**.
- Lean = network egress 없는 로컬 외부 검증기 → §5.7.12 패턴보다
  trust 등급 높음. ARCHITECTURE 트러스트존 신규 항목 여부는 Phase A
  종료 시 rule #4 게이트로 판단.

→ **측정 fixture 선을 넘어 수학-특화 feature 를 core 에 추가하는
순간 룰 #1 위반**. 이 선이 본 트랙의 hard boundary.
