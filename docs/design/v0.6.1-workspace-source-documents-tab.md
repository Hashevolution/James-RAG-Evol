# v0.6.1 — Workspace "원본 자료" (source documents) tab

> Status: DESIGN + build. Operator decision 2026-06-22: repurpose the
> dead `검색` placeholder tab into the source-document find→view→edit
> surface it was always meant to be.

## Problem (from the workspace audit)
The "find a source document → read it → edit it" loop was **not wired**
in the workspace, even though every backend piece already exists:

| step | backend (exists) | workspace (before) |
|---|---|---|
| find | `/admin/files/search?q=&root=` | 검색 탭 = empty placeholder |
| view content | `/admin/files/view?root=&path=` (text, ≤1MB) | none (detail = metadata + entity chips only) |
| download | `/admin/files/download?root=&path=` | none |
| edit | `/admin/wiki/edit/*` (by entity name) | only from the CR tab; no link from a found file |

The `/admin/files/*` endpoints were used only by admin.js. The two
stores — **uploads** (original uploaded files) and **wiki** (editable
knowledge entities) — were never bridged in the workspace.

## Design
Replace the `#tab-search` placeholder with a real **원본 자료** tab.

- **Root selector**: 위키(`wiki`) / 업로드(`uploads`) — the two
  `_file_mgmt_roots` that hold source docs (media omitted; not source).
- **Search**: debounced → `GET /admin/files/search?q=&root=` →
  list `{name, path, size, mtime}`.
- **View**: click a result → `GET /admin/files/view?root=&path=` →
  render `content` in a `<pre>`. Non-text (415) / too-large (413) →
  show "다운로드만 가능" with the download link.
- **Actions** on the open file:
  - **편집** — only for `wiki` `.md` files. Opens the existing
    추론편집(wiki-edit) modal, pre-fills `we-name` with the filename
    stem, and triggers its load. `find_entity_file` resolves by stem, so
    a normal entity file loads; a non-entity `.md` falls back to the
    modal's "not found" message (graceful).
  - **다운로드** — `/admin/files/download?root=&path=` (new tab).

All gated by `admin.data` (same as the endpoints) — consistent with the
workspace being an operator surface.

## Scope / non-goals
- No new backend (pure frontend wiring of existing endpoints).
- No full-text search (filename substring only — that is what
  `/admin/files/search` provides; content search is a later cycle).
- Edit stays entity-based (wiki-edit modal); editing raw uploaded
  binaries is out of scope (view/download only).

## Files
- `frontend/workspace.html`: nav label 검색→원본 자료; replace
  `#tab-search` body with search box + root selector + results list +
  view panel + action buttons.
- `frontend/static/workspace.js`: `srcSearch/srcOpen/srcEdit/srcDownload`
  + data-action handlers + `selectTab('search')` focuses the box.
- `frontend/static/i18n.js`: retarget `workspace.tab_search` +
  `workspace.search_title`; drop `workspace.search_placeholder`
  (the coming-soon line); add the new keys.

frontend only, `core/` 0 lines. Mirrors the intro/graph consolidation
pattern (reuse existing endpoints + components).
