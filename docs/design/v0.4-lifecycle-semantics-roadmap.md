### 1.1 핵심 목표

1. **Layer 4 6 영역 (T1-T6) 구현** — Mem0 / Letta / Cognee 와 명확 차별화

4. **i18n contract 유지** — v0.4 신규 UI-노출 라벨 (reviewer_rank /
   approval_state / contradiction reason 등) 은 모두 backend `label_key`
   패턴 필수. 2026-05-22 i18n sweep 으로 7 backend 모듈에 invariant
   가 되었음 (`tests/test_*_i18n.py` contract test 5개)
5. **Bench gate 준수** — `core/retrieval` / `core/graph` / `core/reasoning`
   를 건드리는 PR (T1 expiration cascade, T6 invalidation cascade 등)
   은 STEP 7 bench 결과를 PR body 에 paste (CLAUDE.md rule 2)
6. **Module size gate 준수** — 신규 `core/lifecycle/*.py` 모듈 각 < 20 KB
   (CLAUDE.md rule 5). 초과 시 분할

### 1.2 6 영역 목표 (T1-T6)

| Stage | 영역 | 핵심 목표 |
|---|---|---|
| **T1** | Temporal Validity & Expiration | Fact 의 valid window 정의, 만료 시 자동 expiration cascade |
| **T2** | Deterministic Contradiction Arbitration | 동일 (s, p) 의 다른 o 발생 시 LLM 미사용 결정론적 처리 |
| **T3** | Evidence Aging & Trust Decay | Source weight 의 시간 기반 자동 decay (분야별 함수) |
| **T4** | Reviewer Authority Hierarchy | Manual source 의 다층 governance (analyst / manager / admin) |
| **T5** | Replayable Audit Graph | Event-sourced reconstruction, 임의 시점 graph 재현 |
| **T6** | Causality Chain Tracking | Derived fact 의 base fact 추적, 자동 invalidation |

## 4. T1 — Temporal Validity & Expiration

### 4.1 Problem

현 cascade 는 시간 차원 없음. `report_Q1.pdf` 가 영원히 source 로 남음.

실제 운영:
- 분기 보고서 → 1년 후 stale
- 정책 문서 → 개정 시 invalid
- 가격 정보 → 분기마다 갱신

### 4.2 Design

**Validity Window per Source**:
```python
source = {
    "doc_id": "...",
    "weight": 0.7,
    "valid_from": "2026-04-01",
    "valid_until": "2027-04-01"  # None = 무기한
}
```

**Confidence at time t**:
```python
def compute_confidence_with_time(sources, current_time):
    active_sources = [s for s in sources
                      if s["valid_from"] <= current_time < s["valid_until"]]
    return compute_confidence_from_sources(active_sources)
```

**Auto-expiration Cascade**:
- 매일 배치 작업: `valid_until` 경과한 source 자동 archive
- archived source 는 cascade 대상에서 제외, audit log 에 기록
- relation 의 active source 0 → relation 자동 사라짐 (Layer 3 cascade 와 동일 메커니즘)

### 4.3 New Invariants (T1)

| Test | 검증 |
|---|---|
| `test_source_expires_at_valid_until` | valid_until 경과 후 confidence 에서 제외 |
| `test_relation_dropped_when_all_active_sources_expire` | 모든 active source 만료 → relation 자동 제거 |
| `test_valid_until_null_means_indefinite` | null 인 source 는 영구 활성 |
| `test_temporal_cascade_preserves_manual_immunity` | manual source 의 expiration 은 reviewer authority 와 정합 |

### 4.4 Reference Implementation Sketch

```python
# core/relations_schema.py (확장)
def compute_confidence_from_sources(sources, current_time=None):
    """Noisy-OR over active (non-expired) sources."""
    if not sources:
        return 0.0
    p = 1.0
    for s in sources:
        if not isinstance(s, dict):
            continue
        # T1: temporal validity filtering
        if current_time and not _is_active(s, current_time):
            continue
        w = s.get("weight")
        if isinstance(w, (int, float)):
            w_clip = max(0.0, min(1.0, float(w)))
            p *= (1.0 - w_clip)
    return round(1.0 - p, 4)

def _is_active(source, t):
    """Returns True if source is currently valid (T1 logic)."""
    vf = source.get("valid_from")
    vu = source.get("valid_until")
    if vf and t < vf:
        return False
    if vu and t >= vu:
        return False
    return True
```

## 5. T2 — Deterministic Contradiction Arbitration

### 5.1 Problem

두 source 가 다른 tail 주장:
- `report_A.pdf` → "Joby acquired Boeing"
- `report_B.pdf` → "Joby acquired Airbus"

현 Memory Loom Gate 5 는 거부만 함 (둘 다 안 저장). 더 정교한 처리 필요.

### 5.2 Design

**Arbitration Rules** (deterministic, LLM 미사용):

| Rule | 우선순위 | 결정 |
|---|---|---|
| 1. Manual override | 최우선 | reviewer_rank == "admin" 의 manual source 가 무조건 win |
| 2. Higher confidence | 2순위 | source weight 가 더 높은 쪽 win |
| 3. More recent | 3순위 | ts 가 더 최근인 쪽 win |
| 4. Temporal validity | 4순위 | valid_from 이 더 최근 쪽 win (정정본 우선) |
| 5. Default reject | fallback | 둘 다 거부 + audit log |

→ **LLM 미사용**. 모든 rule 결정론적.

### 5.3 New Invariants (T2)

| Test | 검증 |
|---|---|
| `test_admin_manual_overrides_any_extract` | admin manual source > extract |
| `test_higher_confidence_wins_among_equal_role` | 동일 role 시 confidence 비교 |
| `test_more_recent_wins_among_equal_confidence` | confidence 동일 시 ts 비교 |
| `test_contradictions_logged_in_relation_metadata` | 거부된 후보 metadata 에 기록 |
| `test_arbitration_is_deterministic` | 동일 input → 항상 동일 output (idempotent) |

### 5.4 Reference Sketch

```python
# core/lifecycle/contradiction_arbitrator.py (신규)
def arbitrate_contradiction(
    existing: Dict, candidate: Dict
) -> Tuple[Literal["accept", "reject", "supersede"], str]:
    """결정론적 충돌 중재.
    
    Returns:
        (action, reason_code)
    """
    # Rule 1: admin manual override
    if (candidate.get("role") == "manual" and
        candidate.get("reviewer_rank") == "admin"):
        return ("supersede", "admin_override")
    if (existing.get("role") == "manual" and
        existing.get("reviewer_rank") == "admin"):
        return ("reject", "admin_existing")
    
    # Rule 2: confidence comparison
    if candidate["weight"] > existing["weight"]:
        return ("supersede", "higher_confidence")
    if candidate["weight"] < existing["weight"]:
        return ("reject", "lower_confidence")
    
    # Rule 3: timestamp comparison (equal weight)
    cts = candidate.get("ts")
    ets = existing.get("ts")
    if cts and ets and cts > ets:
        return ("supersede", "more_recent")
    if cts and ets and cts < ets:
        return ("reject", "older")
    
    # Rule 4 + 5: fall through to default
    return ("reject", "default")
```

## 6. T3 — Evidence Aging & Trust Decay

### 6.1 Problem

5년 전 source 와 어제 source 가 동일 weight 로 신뢰됨. 부적절.

### 6.2 Design

**Per-Source Aging Function**:
```yaml
source:
  weight: 0.85
  ts: "2026-04-01"
  aging_policy: "exponential"
  half_life_days: 365
```

**Effective Weight at time t**:
```python
def effective_weight(source, current_time):
    base_weight = source["weight"]
    policy = source.get("aging_policy", "none")
    if policy == "none":
        return base_weight
    elif policy == "exponential":
        half_life = source.get("half_life_days", 365)
        days_old = (current_time - source["ts"]).days
        decay_factor = 0.5 ** (days_old / half_life)
        return base_weight * decay_factor
    elif policy == "linear":
        max_age = source.get("max_age_days", 365)
        days_old = (current_time - source["ts"]).days
        return base_weight * max(0, 1 - days_old / max_age)
    # 등등
```

**Domain-specific Defaults**:
- 의료: half_life = 90 일 (6개월)
- 법률: half_life = 730 일 (2년)
- 기술: half_life = 365 일 (1년)
- 인물 정보: half_life = 1825 일 (5년)

## 7. T4 — Reviewer Authority Hierarchy

### 7.1 Problem

`role: manual` 만으로는 governance 부족. analyst 가 잘못 입력한 manual fact 가 admin 검토 없이 영구 보존.

### 7.2 Design

**Reviewer Ranks**:
- `analyst` (lowest) — 일반 사용자, 임시 manual 입력
- `manager` — 검토자, analyst manual 을 supersede 가능
- `admin` (highest) — 최종 권한, 모든 manual 을 supersede 가능

**Approval State Machine**:
```
pending → approved (by manager 이상)
       → rejected (by manager 이상)
       
approved → revoked (by admin)
```

**Hierarchy Rule**:
- analyst manual: 임시 (pending 상태로 시작)
- manager 가 review → approved 또는 rejected
- admin manual: 즉시 approved
- 상위 rank 가 하위 rank 의 결정 override 가능

### 7.3 New Invariants (T4)

| Test | 검증 |
|---|---|
| `test_analyst_manual_starts_pending` | analyst manual → approval_state="pending" |
| `test_manager_can_approve_analyst_manual` | manager 가 analyst manual approval 가능 |
| `test_admin_overrides_manager_decision` | admin > manager > analyst hierarchy |
| `test_pending_manual_is_immune_but_invisible_in_retrieval` | pending 은 retrieval 제외 (visibility=internal) |

### 7.4 Reference Sketch

```python
# core/lifecycle/reviewer_authority.py (신규)
REVIEWER_RANKS = ["analyst", "manager", "admin"]
APPROVAL_STATES = ["pending", "approved", "rejected", "revoked"]

def can_override(actor_rank: str, target_rank: str) -> bool:
    """actor 가 target manual 을 override 할 수 있는가?"""
    return REVIEWER_RANKS.index(actor_rank) >= REVIEWER_RANKS.index(target_rank)

def initial_approval_state(reviewer_rank: str) -> str:
    """신규 manual source 의 초기 approval_state."""
    if reviewer_rank == "admin":
        return "approved"
    return "pending"
```

## 8. T5 — Replayable Audit Graph

### 8.1 Problem

현재 audit log 는 텍스트 jsonl. 임의 시점의 graph 상태를 재구성하기 어려움.

### 8.2 Design

**Event Sourcing 추가**:
- 모든 mutation 을 event 로 기록 (Layer 3 cascade 와 병행)
- Event 만으로 임의 시점 graph 재구성 가능
- 기존 state-based 와 dual 운영

**Event Schema**:
```json
{
  "event_id": "evt_2026_05_21_001",
  "ts": "2026-05-21T12:21:00.123Z",
  "type": "source_added|source_removed|relation_dropped|...",
  "actor": "user:alice|system:cascade|llm:extract",
  "subject": {"entity_id": "...", "relation_idx": 3},
  "before": {...},
  "after": {...},
  "causality": {
    "triggered_by": "evt_...",
    "triggers": ["evt_..."]
  }
}
```

**Replay Engine**:
```python
def reconstruct_graph_at(target_time, event_log_path):
    """event log 의 시작부터 target_time 까지 replay → graph 재구성."""
    graph = empty_graph()
    for event in iter_events(event_log_path):
        if event["ts"] > target_time:
            break
        apply_event(graph, event)
    return graph
```

## 9. T6 — Causality Chain Tracking

### 9.1 Problem

추론된 fact 의 base fact 가 사라지면 derived fact 도 invalid 되어야 함. 현재는 추적 안 됨.

예시:
- base fact: "Joby 본사 in California" (from doc A)
- derived fact: "Joby 미국 회사" (inferred from base)
- doc A 삭제 시 → base fact 사라짐 → derived 도 자동 invalidate 되어야

### 9.2 Design

**derived_from Field**:
```yaml
relation:
  head: Joby
  tail: USA
  predicate: BASED_IN
  inferred: true
  derived_from:
    - base_fact_id: "fact_xxx"   # (Joby, BASED_IN, California)
      derivation: "transitive"
    - base_fact_id: "fact_yyy"   # (California, IS_IN, USA)
      derivation: "transitive"
```

**Invalidation Cascade**:
- Base fact 의 confidence 가 임계값 미만으로 떨어지면 → derived 도 invalidation 후보
- 또는 base fact 자체가 사라지면 → derived 즉시 invalidation

### 9.3 New Invariants (T6)

| Test | 검증 |
|---|---|
| `test_derived_fact_invalidated_when_base_removed` | base 제거 → derived 자동 사라짐 |
| `test_partial_base_loss_reduces_derived_confidence` | base N 개 중 일부만 사라지면 derived confidence 감소 |
| `test_causality_chain_acyclic` | derived 가 자신을 base 로 가질 수 없음 (cycle X) |
| `test_inferred_field_set_correctly` | inferred=true 인 relation 만 derived_from 보유 |

### 9.4 Reference Sketch

```python
# core/lifecycle/causality.py (신규)
def invalidate_derived_facts(base_fact_id: str) -> List[str]:
    """base fact 가 제거됨 → 의존하는 derived fact 들 식별 후 invalidation."""
    invalidated = []
    for entity_path in iter_entity_files():
        for relation in entity.relations:
            if not relation.get("inferred"):
                continue
            for derivation in relation.get("derived_from", []):
                if derivation["base_fact_id"] == base_fact_id:
                    relation["sources"] = []  # 강제 cascade drop
                    invalidated.append(relation["id"])
    return invalidated
```

```python
    source.setdefault("half_life_days", None)
    if source.get("role") == "manual":
        source.setdefault("reviewer_rank", "analyst")     # T4
        source.setdefault("approval_state", "approved")   # backward compat
    return source
```

→ 모든 기존 source 는 backward-compatible (default = none / approved).

### 10.2 Audit Migration

기존 jsonl audit → event store dual write:
- v0.3 audit 유지 (legacy)
- v0.4 부터 event store 에 추가 기록
- 일정 기간 dual write → 검증 후 event store 전환
