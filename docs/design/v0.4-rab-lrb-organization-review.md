**핵심 정정 한 가지**: 제안문의 "개인 명의면 죽고 중립 표준으로 보이면
산다"는 방향은 맞지만, **중립성은 repo 소속이 아니라 구조에서 나온다**.
Org 이전만으로 중립이 되는 게 아니라, (a) frozen spec + deterministic
scorer, (b) 제작자 외 독립 SUT ≥ 1, (c) 벤치마크 점수가 아닌 gap
structure 헤드라인 — 이 세 가지가 실질 조건이며, RAB는 (a)(c)를 이미
충족하고 (b)가 미충족이다. Org 이전은 (b)를 얻기 위한 **장벽 제거**로
정당화되는 것이지, 그 자체가 중립성 획득이 아니다.

## 2. 4단계 사다리 적합성 판단

### 2.1 1단계 — GitHub Org + RAB 독립 repo: **조건부 타당, 권고**

**타당한 근거:**

1. **비용 0, 가역적.** 실패해도 잃는 것이 org 계정 하나.
2. **시퀀싱이 맞다.** arXiv preprint는 repo URL을 본문에 박는다.
   8월 2일(EU AI Act 발효) 전 제출이 목표라면, **org/repo 이전 →
   preprint URL 갱신 → Zenodo 단독 DOI → arXiv 제출** 순서가 유일하게
   재작업이 없는 경로다. 제출 후 이전하면 URL이 죽거나 redirect에
   의존한다. 즉 "지금 하거나, 제출 후 한참 뒤에 하거나" 둘 중 하나이고
   지금이 싸다.
3. **벤더 중립성 논거는 실재한다.** 벤치마크 선례 (SWE-bench,
   HELM, MLPerf/MLCommons) 모두 SUT 벤더와 분리된 명의가 채택의
   전제조건이었다. RAB의 현재 헤드라인 측정이 "JAMES AC/RF/PC 1.000
   vs Baseline 0.275"인 만큼, JAMES repo 안에 있으면 이해충돌 의심은
   구조적으로 정당하다 (실제로 SPEC §6이 이를 의식해 gap-structure
   헤드라인 조항을 박아둔 상태).
4. **분리가 audit-benchmark의 자기증명이 된다.** pre-registration
   규율의 증거가 커밋/PR 이력에 있으므로, history-preserving 분리
   (`git filter-repo`)는 "재검증 가능한 audit 벤치마크가 자기 이력도
   재검증 가능하게 보존했다"는 on-brand 신호다.

**조건 (이게 빠지면 부적합):**

- **"중립 표준" 셀프-라벨링 금지.** 현재 RAB는 단독 저자, 어댑터 4종
  전부 동일 저자 작성, 외부 사용자 0이다. 이 상태에서 GOVERNANCE.md에
  위원회 구조를 그려 넣는 것은 governance theater이고, 이 프로젝트의
  honest-framing 룰 (`feedback_finding_size_honest_framing`) 위반이다.
  정직한 표기는 *"single-maintainer benchmark seeking co-maintainers
  and independent SUT submissions"*.
- **중립성의 실질 조건 (b) — 제작자 외 독립 SUT ≥ 1 — 을 분리 후 첫
  마일스톤으로 명시.** 자연 후보는 ActiveGraph (co-invention 상호
  인지 상태). 단, `feedback_eval_cycle_vs_collab_arc_separation` 룰에
  따라 **자동 연결 금지** — ActiveGraph 어댑터는 별도 합의된 collab
  arc로만 진행한다.
- **JAMES는 "참가자 중 하나"로 강등.** 어댑터 배치로 구조화:
  RAB repo = spec + driver + scorer + reference + baseline0/1 (중립
  자산만), `adapters/james.py` 는 **JAMES repo 쪽으로 이동** (SUT
  어댑터는 SUT와 함께 산다). 이것이 제안문 ①의 "JAMES는 RAB의 참가자"
  구조를 코드 레벨에서 실현하는 방법이다.

### 2.2 2단계 — Fiscal Host: **타당하나 시기상조**

- 설명 자체는 정확하다 (Open Collective / SF Conservancy / NumFOCUS의
  법적·재정 우산 기능). 단 **현재 들어올 돈이 0이고 지출 주체가 필요한
  계약도 0**이므로, 지금 신청하는 것은 관리 오버헤드만 산다.
- NumFOCUS/Conservancy는 심사형이라 외부 사용자 0인 프로젝트는 어차피
  통과가 어렵다. Open Collective는 진입장벽이 낮지만 같은 이유로 급할
  것 없다.
- **준비만 해 둘 것**: 1단계 분리 시 자금 수령 구조를 막는 결정(예:
  개인 명의 스폰서 버튼)을 하지 않는다. 트리거는 LICENSE_PLAN.md
  T2(상업 문의)와 동형으로 정의 가능 — "외부 기여자/기관이 비용이
  드는 요청(CI 자원, 측정 의뢰, 로고 사용)을 처음 하는 시점"에 개시.
- 제안문의 단서 ("소속기관 복무 담당 사전 확인 권장")는 옳고, §2.3과
  묶어 처리한다.

### 2.3 3단계 — 비영리 사단법인/연구회: **방향 타당, 전문가 확인 전제**

- 국가공무원 복무규정상 영리업무 금지(제25조)·겸직허가(제26조) 구분과
  "비영리 단체 임원은 허가 트랙"이라는 제안문 서술은 일반론으로는
  통상적인 이해와 부합한다. **그러나 이 판단은 코드베이스가 검증할 수
  있는 영역이 아니고, 소속기관별 내규·해석 차이가 실재한다.** Fiscal
  host 경유 자금조차 "계속성 있는 영리 종사"로 해석될 여지를 제안문
  스스로 인정하고 있다.
- **권고**: 3단계는 2단계 트리거 발화 전에는 착수하지 않으며, 착수
  전에 (i) 소속기관 복무 담당 서면 확인, (ii) 필요시 행정사/변호사
  자문을 선행 조건으로 박는다. 이 문서는 그 이상을 판단하지 않는다.

### 2.4 4단계 — 영리법인: **현 시점 판단 불요, 단 한 가지 선결정 필요**

- "신분 변동 후, 1–3단계 자산을 초기 자산으로" — RedHat/Grafana 모델
  인용은 적절하고, `docs/LICENSE_PLAN.md`의 트리거 체계(T4 = 상업화
  선언)와 이미 정합이라 새 결정이 필요 없다.
- **단 하나, 지금 결정해야 하는 것**: 분리되는 RAB repo에 CLA §4-bis
  (재라이선스 grant)를 가져갈 것인가. **권고: 가져가지 않는다.**
  표준 후보 벤치마크에 "운영자가 장래 유료 라이선스로 전환할 수 있음"
  조항이 붙어 있으면 중립성 주장과 정면 충돌한다. 수익화 옵션은
  JAMES(모체) 쪽에 남기고, RAB는 plain MIT + DCO(또는 CLA 없이)로
  간다. 이것이 제안문 4단계의 "표준은 중립 조직에, 수익화는 별도
  회사에" 원칙의 라이선스 버전이다. (LICENSE_PLAN.md의 T1–T5 트리거
  체계는 JAMES repo에만 적용됨을 분리 시점에 명문화.)

## 4. LRB — 분리 보류 권고와 선행 조건

LRB를 RAB와 동시 분리하자는 판단은 **현 시점 부적합**. 비대칭 근거:

1. **헤드라인 구조가 다르다.** RAB의 헤드라인은 gap structure(어떤
   계측 계층이 무엇을 잃는가)이고 JAMES 점수가 아니다. LRB의
   헤드라인은 V<N<J — 즉 "JAMES 명명의 전략이 4/4 모델에서 이긴다"
   — 로, 외부에서 보면 JAMES 우위 시연 벤치마크다. 이대로 분리하면
   "중립 표준" 포지셔닝이 RAB보다 약하고, 오히려 RAB의 중립성
   주장까지 오염시킬 수 있다 (같은 org에서 한쪽은 중립, 한쪽은
   자기-우위 헤드라인).
2. **측정이 아직 움직인다.** v0.2.3b S3 cross-model full measurement
   (~4–6h)가 운영자 잔여 항목이고, HR axis(v0.2.4)는 partial. RAB처럼
   spec frozen 상태가 아니다.
3. **분리 자체는 기술적으로 더 쉽다** (core import 0) — 즉 보류
   비용이 낮고, 언제든 따라갈 수 있다.
