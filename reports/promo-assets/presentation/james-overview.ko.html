01 · 개념

자메스(JAMES)가 뭐예요?

한 문장으로: 내 컴퓨터 안에서만 일하는, 입이 무거운 도서관 사서.

쉬운 비유

📚 내가 준 책(PDF·문서·사진)을 전부 읽고 기억해요. 질문하면 답을 주는데, "몇 번째 책 몇 페이지에서 봤는지"까지 짚어줘요. 그리고 그 책들을 절대 밖으로 안 가져나가요.

🏠
내 컴퓨터 안에서 (로컬)
인터넷에 자료를 안 보냄. 노트북 한 대 + Ollama로 동작.
🔎
근거를 보여줌
답마다 출처 문서 + 그래프 경로를 첨부. 근거 없으면 "근거 없음" 표시.
✅
사람이 승인
시스템이 스스로 바뀌려면 반드시 사람의 승인 도장이 필요.
📌 근거 미션 정의 — "explicit reasoning paths(근거 경로) + role-based access(권한) + human-supervised improvement(사람 감독 개선)" (docs/ARCHITECTURE.md §1). 설계 원칙 8가지 중 1번 Local-first, 2번 Evidence-based reasoning, 5번 Human-supervised evolution. ERP·회계·예약 같은 시스템을 대체하지 않고 그 위에 얹는 분석/검색/정책 레이어(§2 Non-goals).
02 · 차별점

보통 AI와 뭐가 달라요?

쉬운 비유

🗣️ 보통 챗봇 — "어디서 들었는진 모르지만 그냥 술술 말함" (가끔 지어냄).

👉 자메스 — "이 답은 3번 문서 + 그래프 47개 경로에서 나왔어"라고 손가락으로 짚어줌.

  • 지어내면 들킴 — 모든 답은 출처와 그래프 경로를 달고 나옴
  • 왜 그 답인지 되돌려보기 — trace_id 하나로 전 과정 재생
  • 아무나 못 봄 — 사람마다 볼 수 있는 자료가 다름(권한)
📌 근거 NL-throughout + Trace replay invariant — 모든 추론 단계(planner·rerank·reflect·verify·tool)가 audit_bridge에 1행씩 기록, "왜 X라고 답했나?"를 사후에 재구성 가능 (scripts/replay_trace.py <trace_id>, ARCHITECTURE §5.7.2). RAGAS 측정값: faithfulness(근거 충실도) 1.000, context_precision/recall 1.000 (eval/RESULTS.md).

04 · 동작 원리

질문이 들어오면 9개의 검문소를 지나가요

쉬운 비유

🚦 공항 보안검색처럼, 질문 → 답까지 줄줄이 검문소를 통과해요. 각 검문소는 자기 일을 하고 기록을 남겨요. 그래서 나중에 "왜 이렇게 답했지?"를 전부 되감기할 수 있어요.

1보안 필터→ 2질문 라우터→ 3질문 재작성→ 4하이브리드 검색→ 5재정렬(Rerank)→ 6그래프 탐색→ 7추론·검증→ 8출력 필터(PII·권한)→ 9감사 로그

검색은 벡터 60% + BM25 20% + 키워드 10% + 이름 10%를 섞은 하이브리드. 형식 질의어(SQL/SPARQL)로 번역하지 않고 자연어 그대로 흐릅니다.

📌 근거 파이프라인 도식은 README.md "Architecture" + docs/ARCHITECTURE.md §5.7. 모든 단계가 하나의 trace_id로 1행씩 기록되어 전 과정 재구성 가능(trace-replay invariant). 재정렬기(cross-encoder MiniLM)는 v0.3 기본 ON.
05 · 안전장치

도서관에 출입증이 있어요

쉬운 비유

🎫 손님마다 "어느 책장까지 들어갈 수 있는지" 출입증이 달라요. 나쁜 쪽지(해킹 명령)가 책 속에 숨어 들어와도, "명령은 빼고 내용만" 걸러서 읽어요.

  • 역할 4단계 external < employee < manager < admin
  • 민감도 4단계 자료마다 등급(RBAC + ABAC)
  • 비밀키 없으면 아예 안 켜짐 (insecure 기본값 없음)
  • 감사 로그는 append-only — 승인은 적용 '전에' 기록

09 · 연구 성과

"베껴 쓰기는 공짜, 새 생각은 품이 든다"

쉬운 비유

📝 AI가 그대로 베껴 답할 때(substitution)는 매번 똑같이, 아주 빠르게(0.8초) 나와요. 하지만 새로 생각해서 답할 때(synthesis)는 5배 느리고 매번 달라져요. 이 '비용의 비대칭'을 숫자로 측정했어요.

  • 베껴 쓰기 — 62토큰 고정, 1/20 unique (샘플링 통과)
  • 새 생각 — 7단계 작업무게에 따라 27배 차이
  • 모델이 클수록 새 생각이 ~9배 토큰 효율적

13 · 상업화 분석

돈 버는 제품이 되려면 아직 뭐가 필요할까?

엔지니어링 토대는 강하지만, '상업적 가치'까지는 솔직히 빈칸이 많습니다. 가진 것(✓)과 필요한 것(△)을 나눠봤어요.

  • ✓탄탄한 토대 — 보안 보증·평가 베이스라인·OpenSSF 배지·190 PR·1,800+ 테스트. 신뢰의 출발점은 마련됨.
  • △실사용자·채택 — 현재 stars 13 / 외부 deployer 0. 임계값(1,000 stars, 10 deployer)까지 거리가 큼. 채택 인프라(/feedback)도 미설치.
  • △운영 성숙도 — HTTPS·SSO·SAML·멀티테넌시·백업/복구 CLI·Prometheus/OpenTelemetry. 전부 v1.0 과제로 아직 없음.
  • △외부 보안 검증 — 지금은 합성·내부 테스트. 외부 레드팀 prompt-injection 패스가 v0.5 필수.
  • △첫 도메인 PoC — 카페 1곳에서 6개월 무회귀 운영 = 모든 영업·투자의 핵심 증거물.
  • △지속가능성(Bus factor ≥ 2) — 현재 1인 + AI. 30일 부재에도 견디는 체계 필요.
  • △수익 후크 — MIT 유지 중. Open Core 전환 인프라(CLA·plugin license 필드)는 준비됐으나, 매출 모델은 미확정.
📌 근거 필요 항목은 ROADMAP.md v1.0 deliverables + PLATFORM_READINESS.md Gate v1.0과 정확히 일치. 자본 경로(공개 요약): 예비창업패키지(비희석) → 카페 PoC → 시드 → Series A (v0.2.1-business-track.md §4). 구체 영업·재무는 비공개 노트.
