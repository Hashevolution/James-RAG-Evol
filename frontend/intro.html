감사가능한 지식 추론 운영체제

사내 지식을 검색·추론하고, 누가 무엇을 언제 바꿨는지 모두 기록하며, 필요할 때 과거 어느 시점으로든 되돌릴 수 있습니다.

챗 시작 워크스페이스 관리자
검색 사내 문서에서 답을 찾고, 답의 근거를 추적할 수 있습니다.
감사 로그 누가 어떤 변경을 언제 했는지 모두 기록됩니다.
변경 검토 누군가 변경을 제안하면, 운영자가 승인 / 거부할 수 있습니다.
시점 복원 과거 어떤 순간의 상태로든 시스템을 되돌려 볼 수 있습니다.

차별점: 모든 변경을 삭제 대신 유효구간(validity-window)으로 보존해, 현재 답변 품질을 지키면서도 재현 가능한 감사(replayable-audit) 와 시점 복원(time-travel) 을 함께 제공합니다.

SEKOS 에 처음 오신 분 안내

SEKOS 는 회사의 지식을 안전하게 저장하고, 누가 무엇을 언제 바꿨는지 남기고, 필요할 때 과거 시점으로 되돌릴 수 있는 시스템입니다. 이 안내는 다섯 가지 핵심 동작을 5 분 안에 배웁니다.

개발 지식이 없어도 됩니다. 각 단계는 화면 안내만 따라 하시면 됩니다. 언제든 위쪽 "챗 시작" 으로 안내를 닫을 수 있고, 다시 보고 싶을 때는 관리자 페이지에서 재시작할 수 있습니다.

검색 — 답 찾기

검색은 가장 자주 쓰게 될 기능입니다. 평소처럼 한국어로 질문을 입력하시면 됩니다.

예시 질문
  • 우리 회사 휴가 정책은 어떻게 되나요?
  • 지난 분기 매출 보고서 핵심 요약해 줘
  • 앤스로픽의 CEO 가 누구야?

답은 항상 근거 문서 링크와 함께 표시됩니다. 답 옆의 출처 표시를 누르면 어떤 문서에서 어떤 부분을 가져왔는지 확인할 수 있습니다. 시스템이 답을 모르겠으면 "정보가 없습니다" 라고 솔직하게 답합니다 — 추측해서 잘못된 정보를 만들지 않도록 설계되어 있습니다.

안내를 마친 뒤 메인 채팅에서 직접 질문을 입력해 보세요.

감사 로그 — 누가 무엇을 언제 바꿨나

모든 검색, 모든 업로드, 모든 변경이 감사 로그에 기록됩니다. 법규 (EU AI Act / GDPR / SOC 2) 가 요구하는 추적성을 자동으로 만족합니다.

자주 묻는 질문
  • "지난주 휴가 정책 문서를 누가 마지막으로 바꿨지?"
  • "이 답이 어제와 다른데, 그 사이에 무슨 변화가 있었지?"
  • "X 라는 직원이 이번 달에 검색한 내용 전부 보여줘"

관리자 페이지의 감사 로그 탭에서 모든 기록을 시간 순으로 볼 수 있습니다. 사용자별 / 카테고리별 / 키워드별로 필터링 가능하며, CSV / PDF 로 내려받을 수 있습니다.

안내를 마치면 관리자 → 감사 로그 에서 직접 살펴볼 수 있습니다.

변경 검토 — 승인할까요?

직원이 새 문서를 업로드하거나 기존 정보를 수정 제안하면, 그 변경은 승인 대기 (Pending) 상태로 들어갑니다. 운영자가 검토해서 승인할 때까지 시스템에 반영되지 않습니다.

대시보드에서 보는 화면
  • 왼쪽 = 현재 내용, 오른쪽 = 변경 제안 (다른 부분 표시됨)
  • 누가 (사용자) 언제 (시각) 무엇을 (차이) 왜 (제안 사유)
  • "승인" 또는 "거부" 버튼 한 번이면 끝

승인 / 거부 시 운영자의 신원이 암호학적으로 (OIDC 또는 운영자 ID) 함께 기록됩니다. 누가 무엇을 승인했는지 사후 위조 불가능합니다.

관리자 → Change Review 에서 대기 중인 변경을 처리합니다.

시점 복원 — 지난주 상태로 돌아가기

실수로 문서를 삭제했거나, 잘못된 정보가 한동안 시스템에 있었다면, 과거 어느 시점의 상태로든 시스템을 되돌릴 수 있습니다.

3 단계로 시점 복원
  1. 관리자 → 그래프 → Time-Travel 에서 돌아갈 시점 선택 (예: "2026-06-10 오후 3시")
  2. "그때의 시스템 vs 지금" 비교 화면에서 차이 확인
  3. 원하면 "복원" 또는 "특정 변경만 되돌리기" 버튼 클릭

복원 자체도 감사 로그에 기록됩니다. 즉 "어제 14시 상태로 되돌렸음" 이 그대로 남아서, 나중에 누군가 "왜 이렇게 되어 있지?" 라고 물으면 설명할 수 있습니다.

안내가 끝납니다. 이제 관리자 페이지로 이동해서 직접 사용해 보세요.

관리자 페이지로 →

SEKOS 의 화면에 등장하는 기술 용어들을 평이한 한국어로 설명합니다. 모르는 용어가 보이면 이 페이지에서 검색하거나, 다른 페이지에서 점선 밑줄이 그어진 단어 위에 마우스를 올리면 같은 설명이 툴팁으로 나타납니다.

기본 개념

RAG (Retrieval-Augmented Generation)
질문에 답할 때, LLM 이 가진 지식만 쓰지 않고 먼저 사내 문서를 검색한 뒤 그 결과를 근거로 답을 만드는 방식. SEKOS 가 기본적으로 동작하는 방식입니다.
Graph-RAG (그래프 기반 RAG)
단순 문서 검색에 더해 온톨로지 그래프 (개념 간 관계망) 를 통해 답을 찾는 방식. 여러 문서에 흩어진 정보를 연결해서 답할 수 있습니다.
Entity (엔티티)
시스템이 알고 있는 한 개의 "것" — 사람, 조직, 개념, 문서 등. 예: "앤스로픽" / "휴가 정책 v3" / "김철수".
Relation (관계)
엔티티들 사이의 연결. 예: "앤스로픽 ─CEO─ 다리오 아모데이", "휴가 정책 v3 ─supersedes─ 휴가 정책 v2".
Ontology (온톨로지)
엔티티의 종류 + 관계 종류 의 정의 체계. 예: 회사 도메인은 "사람 / 조직 / 문서 / 정책" 같은 엔티티 종류, "WORKS_AT / SUPERSEDES / APPROVED_BY" 같은 관계 종류로 구성.
Embedding (임베딩)
텍스트를 숫자 벡터로 변환한 것. 이를 통해 "비슷한 의미" 를 가진 문서를 빠르게 찾을 수 있습니다.

감사 + 시점

Audit log (감사 로그)
시스템에서 일어난 모든 동작의 기록. 누가 언제 어떤 질문을 했는지, 어떤 문서를 봤는지, 어떤 변경을 했는지 모두 저장됩니다. 위조 불가능 (append-only).
trace_id (추적 ID)
한 번의 질문/답변 흐름 전체를 고유하게 식별하는 ID. 나중에 "이 답이 어떻게 만들어졌지?" 추적할 때 사용. 모든 audit log 행에 함께 기록됩니다.
Replay (재생)
과거 어떤 시점의 시스템 상태를 바이트 단위로 똑같이 재구성 하는 기능. audit log 만 있으면 어느 시점이든 재현 가능.
Time-travel (시점 복원)
관리자 → 그래프 페이지에서 시점 선택 → 그 시점의 시스템 상태를 보거나 되돌리는 기능. 실수 복구 + forensic 분석에 사용.
Supersede (관계 갱신)
예: "휴가 정책 v3 가 v2 를 supersede 한다" = 더 새로운 버전이 이전 버전을 대체. 이전 버전은 지워지지 않고 체인 형태로 보존되어, 시점 복원이 가능합니다.
Cascade (연쇄 무효화)
한 문서를 삭제했을 때 그 문서를 근거로 한 다른 정보들을 자동으로 비활성화하는 동작. "이 정보의 근거였던 문서가 없어졌으니 정보도 의심스러움" 표시.

답변 품질

Abstention (회피)
시스템이 답을 모를 때 "정보가 없습니다" 라고 솔직하게 답하는 것. 추측해서 잘못된 답을 만드는 것보다 회피가 옳은 행동입니다.
Hallucination (환각)
LLM 이 사실이 아닌 내용을 그럴듯하게 만들어내는 현상. SEKOS 는 회피 + 근거 표시로 환각을 최소화합니다.
Citation (근거 인용)
답변에 어떤 문서의 어느 부분을 사용했는지 출처를 함께 표시하는 것. 답을 검증 + 재확인할 수 있게 합니다.
Path coverage (경로 적중률)
질문에 답하는 데 필요한 실제 근거 문서를 시스템이 얼마나 찾았는지 측정한 비율. SEKOS Graph-RAG = 0.41 (벡터 검색만 쓰면 0.00).

보안 + 권한

RBAC (역할 기반 접근 제어)
사용자의 역할에 따라 무엇을 볼 수 있는지 결정. 예: "admin / employee / external" 역할별로 접근 가능 자료가 다름.
ABAC (속성 기반 접근 제어)
역할 + 문서 속성 (예: "기밀 등급") 의 조합으로 접근을 결정. RBAC 보다 세밀한 통제.
OIDC (OpenID Connect)
회사의 SSO (Single Sign-On) 시스템과 SEKOS 를 연동 하는 표준. SEKOS 직접 비밀번호를 받지 않고 회사 IdP 에 위임.
Approval evidence (승인 증거)
변경 승인 시 운영자의 신원을 암호학적으로 기록한 정보 (SSO 토큰 또는 OS 사용자 ID 의 해시). 사후 위조 불가능.
CSP (Content Security Policy)
브라우저가 어떤 스크립트/스타일을 실행할 수 있는지 제한 하는 보안 정책. XSS 공격 방어.
Tenant (테넌트)
한 SEKOS 인스턴스에 여러 고객사가 들어 있을 때 각 고객사. 예: SaaS 운영 시 acme / globex 가 같은 서버를 쓰지만 데이터는 분리.

운영자 동작

Change Request (CR) (변경 요청)
직원이 정보를 수정하고 싶을 때 만드는 "제안" 상태의 변경. 운영자가 검토 후 승인/거부할 때까지 실제 시스템에는 적용되지 않습니다.
Rollback (롤백)
잘못된 변경을 되돌리는 동작. SEKOS 에는 (a) "최근 변경 되돌리기" + (b) "특정 시점으로 복원" 두 가지가 있습니다.
Contradiction arbiter (모순 중재)
새로 들어온 정보가 기존 정보와 충돌할 때 4 가지 규칙으로 어떻게 처리할지 결정하는 모듈. LLM 호출 없이 결정론적.
Reasoning trace (추론 흔적)
한 번의 질문/답변에서 시스템이 어떤 단계들을 거쳤는지 의 기록. 관리자 → 추론 흐름 보기 페이지에서 시각화하여 볼 수 있음.
검색 결과가 없습니다.

다른 페이지에서 점선 밑줄 이 그어진 단어 위에 마우스를 올리면 같은 설명이 툴팁으로 나타납니다.
